# Batch 2A-2：主动联系与记忆星图规格

## 1. 主动联系与记忆的体验原则

- **主动但克制（Outbox）**：主动联系不使用任何系统级弹窗、红点或强通知。它化作伴侣空间（晶格温室）中“窗边的微光”或“漂浮的信笺”。在免打扰（DND）或安静时段（Quiet Hours）内，微光会进入休眠或完全隐藏，绝不争抢用户的注意力。
- **记忆可见但不压迫（Memory）**：长期记忆拒绝使用传统的“数据库表格”或“卡片墙”。记忆被具象化为“晶体”与“光痕”交织的星图。高维度的核心记忆是明亮的晶体核，零碎的线索则是星尘。用户在其中漫游，而非“管理数据”。
- **控制权、边界与隐私**：
  - **边界**：每封主动信笺均提供轻量的反馈机制（如“触动”、“不合时宜”、“稍后”），以调整 AI 的联系频率与边界。
  - **隐私**：记忆星图提供明确的“遗忘（删除）”与“导出”物理交互，遗忘表现为晶体碎裂消散，导出表现为光芒汇聚成流，赋予用户绝对的数据掌控感。

## 2. 组件规格：OutboxGlint / 主动联系信笺

**职责**：承载 AI 的主动联系信息，处理接收、阅读、反馈及免打扰逻辑。
**DOM 建议**：一个绝对定位的 `<div id="outbox-glint">`（环境中的光点），点击后展开为 `<dialog id="outbox-letter">`（半透明磨砂玻璃质感的信笺）。

**API 映射**：
- `POST /api/proactive/tick`：后台轮询或心跳触发，检查是否有新联系。
- `GET /api/outbox`：获取收件箱内容。
- `POST /api/outbox/receipt`：信笺展开时调用，标记已读。
- `POST /api/outbox/feedback`：用户点击反馈按钮时调用。

**状态与视觉**：
- **默认/空（Empty）**：隐藏，或仅作为环境背景中极弱的光晕。
- **加载（Loading）**：光点呈现平缓的呼吸频闪。
- **未读（New/Unread）**：窗边出现一颗明亮、带有水波纹呼吸动画的光点（Glint）。
- **已读（Read）**：信笺展开，文字如同水墨或光影在半透明介质上浮现。
- **DND/Quiet Hours**：光点闭合为一颗黯淡的“休眠种子”，悬浮但不闪烁，不触发未读动画。
- **错误（Error）**：光点呈现微弱的闪烁并伴有轻微的视觉干扰（如光晕断裂）。
- **禁用（Disabled）**：超出 `daily_limit` 时，不再出现新光点。

**交互与反馈动作**：
- **Hover**：光点微微放大，散发柔和的光晕。
- **Click**：光点展开为信笺（触发 receipt）。
- **反馈动作**：
  - **“化作微光” (Helpful)**：点击后，信笺化作光点飞入环境，调用 feedback API。
  - **“随风散去” (Inappropriate)**：信笺如沙般消散，调用 feedback API，降低此类联系权重。
  - **“折叠” (Later)**：信笺收缩回光点状态，悬浮在角落。

**移动端**：光点固定在屏幕边缘中上部；点击后信笺作为 Bottom Sheet 从底部升起，占据屏幕下半部分，背景模糊。

**验收标准**：
1. 纯 CSS 实现光点的呼吸与水波纹展开动画，无卡顿。
2. 准确映射 DND 和 Quiet Hours，期间绝不出现强视觉提示。
3. 反馈动作必须触发 `/api/outbox/feedback` 并伴随相应的消散/收起动画。

## 3. 组件规格：MemoryConstellation / 记忆星图

**职责**：以非线性、非表格的形式可视化长期记忆，支持查看、编辑、遗忘和导出。
**DOM 建议**：全屏 `<canvas id="memory-canvas">` 用于绘制星图连线与粒子，上层叠加 `<div id="memory-ui-layer">` 用于展示 HTML 文本节点和操作面板。

**API 映射**：
- `GET /api/memory`, `/api/memory/threads`, `/api/memory/links`, `/api/memory/evidence`：构建星图数据。
- `POST /api/memory/update`：编辑记忆节点。
- `POST /api/memory/forget`：删除记忆节点。
- `GET /api/export`：导出全部记忆。

**状态与视觉**：
- **默认（Default）**：缓慢旋转/漂浮的晶格星图，节点间有微弱的光线（Links）相连。
- **加载（Loading）**：星图从中心向外逐层点亮。
- **空（Empty）**：仅有几颗初始的“星尘”，中央提示“记忆正在孕育”。
- **编辑（Editing）**：选中节点放大，背景变暗，节点旁浮现极简的文本编辑框。
- **遗忘确认（Forget Confirm）**：节点变为红色或冷色调，出现裂纹，等待确认。
- **导出（Exporting）**：所有节点的光芒向屏幕中央汇聚，形成一个高亮的光球。
- **错误（Error）**：界面边缘出现红色流光，提示操作失败。

**交互**：
- **平移/缩放**：鼠标拖拽平移，滚轮缩放（类似地图交互）。
- **点击节点**：聚焦该晶体，侧边或下方浮现 `evidence`（记忆来源/凭证）的半透明面板。
- **移动端**：支持单指拖拽、双指捏合缩放；节点点击后弹出底部面板展示详情。

**验收标准**：
1. Canvas 渲染流畅，支持至少 100 个节点的基础力导向/星图布局。
2. 没有任何传统的 Table、Grid 或 Card 边框，完全契合“晶体/星空”主题。
3. 遗忘操作必须有二次确认（视觉上的“碎裂前兆”），并成功调用 `/api/memory/forget`。

## 4. 记忆数据可视化模型

- **L0-L4 视觉映射**：
  - **L0 (原文/Dust)**：最细微的星尘，不发光，仅在放大时可见。
  - **L1 (摘录/Shard)**：细小的晶体碎片，微光。
  - **L2 (摘要/Crystal)**：成型的多面体晶体，稳定发光。
  - **L3/L4 (主题与核心/Nucleus)**：巨大的、具有内部流光的核心星体，处于星图的视觉中心。
- **空间位置与线条规则 (Threads & Links)**：
  - **Threads** 作为星系的“悬臂”或“晶簇”的主干，同一 Thread 的节点在空间上聚集。
  - **Links** 表现为节点间流动的光纤。当 Hover 某个节点时，与其关联的 Links 高亮，光芒从该节点流向关联节点。
  - **Evidence** 不在星图中直接显示，而是作为节点的“倒影”或“内部折射”，点击节点后在 UI 层解析显示。
- **避免“知识图谱工具感”**：
  - 禁用直线、尖锐的箭头、网格背景。
  - 线条使用贝塞尔曲线，带有透明度渐变。
  - 节点不显示生硬的 Label 标签，而是鼠标靠近时，文字如同在水雾中浮现。

## 5. 核心流程：主动联系收件与反馈

1. **刷新/轮询 (Tick)**：前台静默触发 `POST /api/proactive/tick`。
2. **发现新信笺 (New)**：若有返回且不在 DND/Quiet Hours，调用 `GET /api/outbox`。环境中浮现呼吸光点（OutboxGlint）。
3. **打开 (Open)**：用户点击光点，光点展开为信笺 UI。
4. **回执 (Receipt)**：信笺展开动画完成时，后台触发 `POST /api/outbox/receipt`，标记信笺状态。
5. **阅读 (Read)**：用户阅读信笺内容。
6. **反馈 (Feedback)**：用户点击“化作微光(Helpful)”或“随风散去(Inappropriate)”。触发 `POST /api/outbox/feedback`，信笺执行消散动画，流程结束。
7. **稍后 (Later)**：用户点击“折叠”，信笺收起为光点，不再闪烁。
8. **DND/Quiet Hours**：若在免打扰期间轮询到新消息，光点直接进入“休眠”状态（无动画、极低透明度），直到时段结束。
9. **错误 (Error)**：若反馈 API 失败，信笺微微震动，提示文字“光芒未能传达，请重试”。

## 6. 核心流程：查看、编辑、遗忘与导出记忆

1. **打开星图 (Open)**：点击环境中的“晶体仪”物件，进入全屏星图。调用 `GET /api/memory` 及 `threads/links`。
2. **浏览与聚焦 (Browse/Focus)**：用户拖拽缩放。点击某晶体（L2/L3），晶体居中放大，调用 `GET /api/memory/evidence` 获取来源。
3. **查看凭证 (View Evidence)**：侧边浮现光影面板，展示该记忆的推导来源。
4. **编辑 (Edit)**：点击晶体旁的“雕琢”图标，进入编辑状态。修改文本后，触发 `POST /api/memory/update`，晶体闪烁绿光表示保存成功。
5. **遗忘确认 (Forget)**：点击“粉碎”图标，晶体出现裂纹，提示“是否让这段记忆消散？”。确认后，触发 `POST /api/memory/forget`，晶体碎裂成星尘消失，星图重新布局。
6. **导出 (Export)**：点击全局的“汇聚”按钮，触发 `GET /api/export`。星图所有光点汇聚中心，生成文件下载，UI 提示“记忆已封存”。
7. **撤销/恢复 (Cancel)**：在遗忘确认阶段点击空白处，裂纹愈合，取消操作。
8. **错误恢复 (Error)**：若 Update/Forget 失败，晶体恢复原状，边缘闪烁红光，提示“晶格共振失败”。

## 8. Batch 2A-2 自检清单

1. [ ] Outbox 是否完全摒弃了系统弹窗，改用环境光点（Glint）？
2. [ ] DND 和 Quiet Hours 逻辑是否在视觉上得到了克制的体现（休眠状态）？
3. [ ] `POST /api/proactive/tick` 是否融入了静默轮询机制？
4. [ ] 信笺阅读后是否准确触发了 `receipt` API？
5. [ ] 信笺的“有帮助/不合适/稍后”反馈是否完整映射到 `feedback` API 并有对应动画？
6. [ ] Memory 星图是否使用了 Canvas/SVG 进行非线性布局，而非 Table/Grid？
7. [ ] L0-L4 的记忆层级是否有明确的视觉大小、发光度区分？
8. [ ] `threads` 和 `links` 是否通过空间聚集和光线连接正确可视化？
9. [ ] 点击记忆节点是否能正确调用并展示 `evidence`？
10. [ ] 记忆的 `update`（编辑）操作是否提供了轻量级的内联交互？
11. [ ] 记忆的 `forget`（遗忘）操作是否有明确的二次确认与“碎裂”视觉隐喻？
12. [ ] `export` 流程是否包含了完整的状态（汇聚中、就绪、错误）？
13. [ ] 所有的 API 错误状态是否都有非侵入式的优雅降级或提示？
14. [ ] 移动端是否对信笺（Bottom Sheet）和星图（手势缩放）进行了适配设计？
