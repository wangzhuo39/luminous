# Batch 3B：审计调试、渐进式重构路线与验收清单

本规范定义了「栖光 luminous」从“工具化界面”向“晶格温室”演进的最后一块拼图：如何优雅地处理复杂的技术审计需求，同时不破坏沉浸式的陪伴体验。

---

## 1. 审计与深层调试体验原则

### 1.1 为什么 Trace/Ledger/Jobs 不进入主体验
*   **认知负荷隔离：** 陪伴空间的核心是“当下”与“情感”，而 Trace（追踪）和 Ledger（账本/逻辑链）代表了“过去”与“计算”。将两者混淆会导致用户产生被监视感或系统工具感。
*   **视觉纯净度：** 晶格温室需要大量的负空间（Negative Space）来营造呼吸感，高密度的调试日志会破坏这种美学。

### 1.2 三种视角的区分
*   **普通用户 (User)：** 仅感知“隐私抽屉”。关注点：我的数据在哪？我能删掉它吗？
*   **隐私审计 (Auditor)：** 关注“数据流向”。通过导出功能和简化的审计事件摘要，确认系统没有违规操作。
*   **开发者 (Dev)：** 关注“逻辑链路”。通过 Debug 面板查看 `/api/trace` 的原始时序和 `/api/ledger` 的推理成本。

---

## 2. 组件规格：PrivacyAuditDrawer (隐私审计抽屉)

该组件是用户与系统透明度之间的桥梁，采用“柔和透明”的视觉语言。

*   **职责：** 提供数据导出、记忆清除、隐私政策说明及关键事件摘要。
*   **DOM 建议：** `<aside id="privacy-drawer" class="drawer-hidden">`，内置于 `body` 直接子级，使用 `fixed` 定位。
*   **API 映射：**
    *   `GET /api/export`: 触发数据下载。
    *   `POST /api/memory/forget`: 针对特定记忆条目的删除操作。
    *   `GET /api/trace`: 提取最近 5 条关键行为摘要（如：同步了日历、更新了心情）。
*   **状态管理：** `isOpen`, `isExporting`, `lastAuditTimestamp`。
*   **视觉细节：**
    *   背景：`backdrop-filter: blur(20px) saturate(180%);`
    *   文案：使用“去技术化”语言。例如，不显示“DELETE_RECORD”，显示“抹除这段记忆”。
*   **验收标准：**
    *   从主界面边缘滑动或点击底部微小图标唤起。
    *   导出操作需有明确的进度反馈（Loading 状态）。
    *   手机端占据 90% 宽度，PC 端占据右侧 400px。

## 3. 组件规格：DebugTracePanel (深层调试面板)

这是系统的“机房入口”，仅在特定条件下开启。

*   **功能覆盖：**
    *   **Trace 流：** 实时滚动显示 `/api/trace`。
    *   **Ledger 视图：** 展示 `/api/ledger` 中的推理步长、Token 消耗、决策权重。
    *   **Jobs 状态：** 监控后台异步任务（如：向量数据库索引更新）。
*   **权限/显隐策略：**
    *   默认隐藏。
    *   激活方式：快速点击 Logo 5 次，或 `Ctrl + Shift + D`。
*   **视觉规范：**
    *   采用“暗色矩阵”风格（与主色调形成对比）。
    *   等宽字体 (JetBrains Mono / Cascadia Code)。
    *   高密度布局，支持折叠 JSON 树。
*   **性能影响：**
    *   开启时才建立轮询或监听。
    *   限制 DOM 节点最大数量（如仅保留最近 200 条记录），防止长时间挂载导致页面卡死。
*   **错误状态：** 红色高亮显示 5xx 错误，并提供一键复制错误堆栈的功能。

## 4. 从当前 index.html 到晶格温室的三阶段重构路线

### 阶段 1：视觉骨架 (Visual Skeleton)
*   **目标：** 建立晶格布局，实现背景呼吸效果。
*   **保留 API 逻辑：** 维持现有 `fetch` 逻辑，仅更改数据渲染的目标容器。
*   **替换 DOM 模块：** 将原本散乱的 `div` 封装进 `<main id="greenhouse-core">`。
*   **替换 CSS 模块：** 引入 `variables.css`，定义晶格网格系统（Grid System）。
*   **风险：** 旧样式冲突导致布局错位。
*   **验收标准：** 页面不再有滚动条，背景渐变平滑，基础文字清晰。
*   **回滚点：** 恢复 `index.css`。

### 阶段 2：功能收纳 (Feature Consolidation)
*   **目标：** 将 Chat、Tasks、Memory 等功能移入对应的晶格容器或抽屉。
*   **JS 状态组织：** 引入简单的全局 `Store` 对象，统一管理各模块状态。
*   **替换 DOM 模块：** 移除旧的对话框，替换为 `ChatBubble` 组件和 `TaskGrid`。
*   **风险：** 状态同步失效（例如：发了消息但列表没更新）。
*   **验收标准：** 所有 API 接口调用正常，交互反馈延迟低于 100ms。
*   **回滚点：** 恢复旧的 `renderChat()` 函数。

### 3 阶段：沉浸增强 (Immersion Enhancement)
*   **目标：** 加入微交互、动态光影、隐私审计入口。
*   **JS 状态组织：** 增加 `UIState` 模块，处理动效触发器。
*   **替换 CSS 模块：** 加入 `animations.css`，处理晶格的浮动、模糊切换。
*   **风险：** 低端移动端设备掉帧。
*   **验收标准：** 动画 FPS 稳定在 60，通过隐私审计抽屉能成功导出数据。
*   **回滚点：** 关闭高级 CSS 滤镜。

## 5. 建议 DOM 分区与 JS 状态模块

### DOM 分区建议
```html
<!-- 核心层：晶格背景与光影 -->
<div id="lattice-bg"></div>
<div id="ambient-light"></div>

<!-- 交互层：沉浸式主内容 -->
<main id="stage">
    <section id="chat-zone"></section> <!-- 消息流 -->
    <section id="dynamic-grid"></section> <!-- 任务/日历/活动 -->
</main>

<!-- 覆盖层：功能组件 -->
<nav id="bottom-dock"></nav> <!-- 极简导航 -->
<div id="privacy-drawer-portal"></div>
<div id="debug-panel-portal"></div>
```

### JS 状态模块化 (单文件内建议)
*   **`const LuminousStore = {}`**: 存储 `chatHistory`, `currentState`, `activeTasks`。
*   **`const LuminousRenderer = {}`**: 负责根据 Store 变化更新 DOM 局部。
*   **`const LuminousAPI = {}`**: 封装 `fetch` 请求，统一处理 Header 和错误捕获。
*   **事件委托：** 统一在 `#stage` 上监听点击事件，通过 `data-action` 属性分发逻辑。

## 6. 性能预算与测试建议

*   **首屏加载：** 核心 HTML/CSS/JS 需压缩在 200KB 以内（不含图片）。
*   **动画 FPS：** 在 iOS Safari / Android Chrome 上必须保持 55+ FPS。
*   **内存监控：** 持续运行 2 小时，内存增长不得超过 50MB（防止闭包泄露）。
*   **弱网策略：** API 请求超过 3s 未响应，需在 UI 上显示“感知微弱”的视觉提示，而非生硬的报错。
*   **Mock 模式：** 在 JS 中内置 `USE_MOCK = true` 开关，方便在没有后端时进行 UI 验收。

## 7. 完整设计验收清单

### 视觉与沉浸感 (Visual & Immersion)
1. [ ] 背景晶格是否随鼠标/触摸有轻微的位移感？
2. [ ] 文字阴影是否确保在复杂背景下依然清晰？
3. [ ] 所有的滚动条是否已隐藏或定制为极细的透明样式？
4. [ ] 切换模块时是否有平滑的淡入淡出，而非瞬间消失？
5. [ ] 界面中是否存在超过 3 种以上的非主题色？（应少于 3 种）

### 交互性能 (Interaction)
6. [ ] 按钮点击反馈延迟是否小于 50ms？
7. [ ] 隐私抽屉拉出过程是否丝滑，无卡顿？
8. [ ] 调试面板在加载大量 Trace 数据时是否导致主界面掉帧？
9. [ ] 移动端长按操作是否有触感反馈（如果设备支持）？

### API 与功能 (API & Functionality)
10. [ ] `/api/trace` 的数据是否正确映射到调试面板？
11. [ ] `/api/export` 导出的 JSON 文件格式是否规范？
12. [ ] `/api/memory/forget` 操作后，UI 是否立即移除该条目？
13. [ ] `/api/ledger` 是否能展示出 Token 消耗的数值？
14. [ ] 所有的 404/500 错误是否有非侵入式的 Toast 提示？

### 隐私与安全 (Privacy & Security)
15. [ ] 敏感数据（如记忆内容）在 UI 上是否有“模糊/遮盖”选项？
16. [ ] 导出数据前是否有二次确认弹窗？
17. [ ] 调试面板是否在生产环境下默认关闭？

### 移动端适配 (Mobile)
18. [ ] 底部导航是否避开了 iOS 的 Home Indicator 区域？
19. [ ] 键盘弹出时，输入框是否被正确顶起，不遮挡聊天内容？
20. [ ] 是否支持侧滑返回/关闭抽屉的手势？

## 8. 实施前决策清单 (建议默认值)

1.  **静态资源托管：** 建议所有图标使用 SVG 内联，减少 HTTP 请求。
2.  **字体选择：** 建议优先使用系统原生字体族（Inter, System-ui），仅在 Debug 面板使用等宽字体。
3.  **数据刷新率：** `api/state` 建议 10s 轮询一次，`api/trace` 仅在面板打开时 2s 轮询一次。
4.  **本地存储：** 建议使用 `localStorage` 记录用户的 UI 偏好（如：Debug 面板是否开启过）。
5.  **CSS 方案：** 建议使用 CSS Variables 处理所有主题色，禁止在 JS 中硬编码颜色值。
6.  **错误处理：** 建议默认捕获所有 `fetch` 失败，并记录到内部的一个 `errorLog` 数组中，供 Debug 面板查看。
