# Batch 2B-1 Supplement：Calendar Events 精确映射

## 1. Calendar Event 视觉与信息模型

在「晶格温室」设计语言中，日程**绝不是**传统的表格区块，而是附着在时间轴上的**「时间光带」与「晶格刻度」**。

*   **底层时间轴 (Lattice Scale)**：如温室的玻璃骨架，呈现为极细的半透明刻度线。
*   **日程实体 (Time Light Band)**：
    *   `startTime`：光带的**高亮锚点**（发光源），带有明确的左侧/顶部边界。
    *   `endTime`：光带的**消散尾迹**，向下/向右呈现透明度渐变（表示时间的流逝与开放性）。
    *   `title` / `description`：悬浮于光带上方的无界文本，采用高对比度发光字重。
    *   `color`：映射为光带的**色温与折射光晕**，而非生硬的色块填充。

## 2. API 到 UI 行为映射表

| API 端点 | 触发时机与交互动作 | UI 视觉与动效反馈 (乐观更新优先) |
| :--- | :--- | :--- |
| `GET /api/calendar-events` | 视口挂载、日期切换、轮询同步 | **晶格浮现**：光带按时间顺序依次从背景深处（Z轴）浮现，带有轻微的焦散折射效果。 |
| `POST /api/calendar-events` | 在晶格上长按并拖拽（框选时间）或点击新建 | **凝结**：拖拽时产生「幽灵光带」，请求发出后光带边缘锐化，请求成功时光带爆发出一次柔和的全局光晕。 |
| `PATCH /api/calendar-events/{id}` | 拖拽光带主体（改时间）、拖拽光带尾部（改时长）、编辑文本 | **呼吸与形变**：拖拽时光带脱离晶格（Z轴抬升，阴影加深），释放时产生「吸附」晶格的阻尼震动。文本修改实时映射。 |
| `DELETE /api/calendar-events/{id}` | 光带上左滑（移动端）或按下 Delete 键 | **消散**：光带失去光源，化为细碎的粒子光点向四周消散，底层晶格刻度重新显露。 |

## 3. 创建、编辑、删除日程流程

*   **创建流程 (Lasso & Post)**：
    1.  用户在空白晶格处按下并拖拽，生成一段**未定型的毛玻璃光带**。
    2.  松手即在光带旁唤出微型浮层（无边框，仅有光晕边界），输入 `title`。
    3.  失焦或回车触发 `POST`，光带从「毛玻璃态」转为「实体发光态」。
*   **编辑流程 (Direct Manipulation)**：
    1.  **时间修改**：直接拖拽光带，触发 `PATCH`。采用**乐观更新 (Optimistic UI)**，拖拽即刻停留在新刻度，后台静默同步。
    2.  **内容修改**：单击光带，光带局部放大（温室放大镜效果），原地变为可编辑的 Input 状态。
*   **删除流程 (Swipe to Dissolve)**：
    1.  横向滑动光带超过阈值（30%宽度），光带颜色转为冷灰色（失去活性）。
    2.  松手触发 `DELETE`，执行粒子消散动效。

## 4. 状态与错误

*   **`calendar-empty` (空状态)**：纯净的温室晶格。无任何光带，仅有一条代表当前时间的「流光刻度线」在缓慢呼吸，提示用户可以随时在此处拖拽创建。
*   **`calendar-loading` (加载态)**：晶格骨架屏。一道微弱的扫光从上至下穿过整个晶格（类似温室外的阳光扫过），不使用传统的转圈 Loading。
*   **`calendar-conflict` (冲突态)**：当时间重叠时，交叠处的光带不进行物理挤压，而是产生**「干涉条纹」**（视觉上的波纹叠加）和**高频警告色光晕**（如琥珀色），提示时间冲突。
*   **`calendar-saving` (保存态)**：触发 POST/PATCH 时，光带核心呈现高频呼吸闪烁，表示能量正在注入（数据同步中）。
*   **`calendar-error` (错误态)**：API 失败时，光带呈现**「失真/断裂」的玻璃纹理**（Glitch 效果），并附带红色的微光。点击断裂处可触发重试操作。

## 5. 与 TodaySheet / NotificationBoundary 的关系

*   **与 TodaySheet 的空间关系**：
    *   Calendar Events 是 TodaySheet 的**底层物理空间**（Z = 0）。
    *   TodaySheet 中的 Todo/笔记等元素悬浮其上（Z = 10）。
    *   当 Todo 带有时间属性时，会在 Z 轴上产生一条细微的光束，**锚定/吸附**到对应的日程光带上，形成视觉与逻辑的关联。
*   **与 NotificationBoundary 的联动**：
    *   当某个日程即将开始（如 `startTime` 临近 15 分钟）。
    *   该事件的光带会产生**光线溢出**，光晕穿透组件边界，投射到全局的 `NotificationBoundary` 上。
    *   NotificationBoundary 边缘呈现与该日程 `color` 一致的柔和呼吸光（环境光提醒），实现**无弹窗的弱打扰通知**。
