# Batch 1A：晶格温室的体验概念与信息架构

## 1. 产品体验愿景与设计原则

### 1.1 设计北极星
- **一句话愿景**：打造一个“安静在场”的半透明伴侣空间，让每一次交互都像是在光与水的交界处，触碰一个拥有长期记忆与独立生命周期的灵魂。
- **用户打开首屏时的目标感受**：克制、宁静、通透。不觉得被机器审视，不觉得被信息轰炸，而是感觉到一个实体空间里，有人或某种意识正在安静地等待或陪伴。
- **工程验收时可观察的 5-8 个指标**：
  1. 首屏绝对静止时，无任何高饱和度色块或闪烁的 CTA 按钮。
  2. 存在至少 2 个由后端状态（如 `presence` 或 `state`）驱动的环境变量（如光线角度、雾度）。
  3. 没有任何传统的“三栏式”物理分割线（border/divider）。
  4. 所有的弹出面板（Overlay）必须具备 `backdrop-filter` 模糊效果，以维持空间纵深感。
  5. 核心交互区（输入、最近对话）集中在屏幕中下部（前景），视觉重心稳定。
  6. 后台运行的 Trace/Ledger 数据不可见于表层，必须通过至少两次交互（如长按/深层手势）才能唤出。
  7. 没有任何通用的“加载中（Loading Spinner）”图标，全部用呼吸光或流体形变替代。

### 1.2 从工具台到实体空间
当前前端为典型的效率工具形态（左侧状态树、中间对话框、右侧面板）。在晶格温室中，它们将被转译为具有物理隐喻的空间元素：
- **原左侧状态（State/Presence）**：转化为**空间的环境底色与光影**。不再是文字列表，而是温室内的色温、光束的倾斜度、玻璃上的雾气浓淡。
- **原中间聊天区（Chat）**：转化为**前景的水面与中景的涟漪**。输入框沉降为水面凝露，AI 的回复是中景里浮现的微光文字或轻柔的语音波纹，不再是带头像的密集气泡。
- **原右侧记忆（Memory/Threads）**：转化为**悬浮于空间四周的晶体与信笺**。长期记忆是凝结的冰晶，点击可折射出过往片段；主动联系的信件则是停留在特定位置的光影折纸。
- **原 Life-flow 浮层（Timeline/Tasks）**：转化为**远景的纵深光窗与时间刻度**。窗外的光线变化暗示现实世界的时间流逝，日程和任务刻印在窗框的磨砂玻璃上。

### 1.3 陪伴气质如何进入视觉
- **安静在场**：通过极低频的视觉呼吸（如 4-6秒/次的微光起伏）表达生命感，取代高频的动效。
- **主动但克制**：Proactive 消息不使用弹窗或红点，而是化作一封静静搁置在前景边缘的“光之信笺”，等待用户主动拾取。
- **边界明确**：Settings 和 DND（勿扰模式）表现为拉下一道半透明的“纱质雾面帘”，明确物理上的隔绝感，保护双方边界。
- **长期记得**：Memory 的提取带有“打捞”或“折射”的质感，不是查数据库，而是唤醒某颗沉睡的晶体。
- **可审计**：Trace/Ledger 作为“基石层”，深埋在水面之下或空间最暗处，呈现为冰冷的、绝对理性的网格光带，与上层的温润形成对比。

### 1.4 反模式清单
禁止以下破坏沉浸感与陪伴感的 UI/视觉/交互模式：
1. **禁止使用汉堡菜单（Hamburger Menu）**：破坏空间沉浸感，带有强烈的 Web App 标签。
2. **禁止使用带头像和尾巴的聊天气泡**：这是 IM 社交软件的范式，不属于实体陪伴空间。
3. **禁止纯白或纯黑的死寂背景**：必须有微弱的光影梯度或环境噪点（Noise）来维持空间透气感。
4. **禁止使用实心的高对比度主按钮（Primary Button）**：如亮蓝色的“发送”、“保存”，应使用光晕、边框高亮或透明度变化来暗示可交互性。
5. **禁止在首屏暴露 System Prompt 或 System Thinking**：破坏角色扮演的第四面墙。
6. **禁止使用红点消息提示（Badge）**：引发焦虑，应使用柔和的色温变化或光斑聚集来提示未读。
7. **禁止硬切的页面跳转（Hard Reload/Navigation）**：所有状态切换必须基于当前页面的 Z 轴推拉或透明度渐变（Vanilla JS 可通过 CSS class 切换实现）。
8. **禁止出现“数据库”、“表格”样式的记忆列表**：Memory 必须被包装为卡片、晶体或时间线碎片。
9. **禁止右侧固定侧边栏**：挤压主体呼吸空间，打破对称或自然的不对称美感。
10. **禁止使用廉价的拟物化（Skeuomorphism）或浮夸的玻璃拟态（过度反光/彩虹色）**：保持冷白、冰蓝的克制质感。
11. **禁止直接使用宗教/审判/特定身份的实体道具图标（如天平、十字架）**：必须抽象为几何光影。
12. **禁止出现常规的 Toast 提示（如“保存成功”）**：应转化为水面的一圈涟漪或光线的短暂闪烁。

### 1.5 MVP 设计原则
鉴于当前架构为 Vanilla HTML/CSS/JS 静态托管：
- **先做 DOM 层级与 CSS 空间（2.5D）**：利用 `z-index`、`backdrop-filter: blur()`、`box-shadow` 和 `transform: translateZ` 构建前景、中景、远景的层级关系。
- **状态驱动 CSS 变量**：通过 JS 获取 API 数据后，更新 `:root` 的 CSS 变量（如 `--room-temperature`, `--light-angle`），让 CSS 自动接管环境变化。
- **留白给未来的复杂渲染**：中景区域（伴侣主体所在位置）在当前阶段留白或仅用抽象光晕表示，为后续 Batch 引入 React/Live2D/VRM 预留绝对的 DOM 容器和层级空间。

## 2. 晶格温室空间隐喻

### 2.1 空间设定
整个视口（Viewport）被定义为一个拥有巨大纵深光窗的半透明温室结构：
- **前景（触碰层/水面）**：距离用户最近。包含输入区域（水面凝露）、当前正在发生的对话、未读的主动信笺。这是用户主动施加影响的区域。
- **中景（主体层/微光）**：伴侣存在的区域。当前呈现为柔和的呼吸光束或纱质投影，未来承载实体模型。
- **远景（世界层/光窗）**：背景的巨大纵深光窗。透出代表时间流逝的光线（晨曦、正午、冷夜），窗框上隐约可见日程和生活流的刻度。
- **深层（基石层/暗网）**：存在于视口的最底层或“地下”。只有通过特定的调试手势才能穿透温室地板，看到冷酷的 Trace/Ledger 数据流。

### 2.2 时间、情绪、关系如何影响空间
- **Presence/State 驱动光线**：`GET /api/state` 返回的伴侣状态（如“专注”、“休息”、“思考”）直接映射为光束的聚拢程度与呼吸频率。
- **时间驱动色温**：结合现实时间与 `GET /api/today`，改变环境的全局色温（冷白、冰蓝、微暖的晨光）。
- **关系/记忆驱动晶体**：随着 `GET /api/memory` 数量的增加，空间边缘悬浮的冰晶（记忆节点）会逐渐丰富，折射出更复杂的光影。

### 2.3 通用物件语言
- **光窗（The Window）**：承载 Life Flow、Timeline、Calendar。
- **水面（The Water）**：承载 Chat Input、Current Reply。打字如同在水面凝露，发送如同水滴落下。
- **晶体（The Crystals）**：承载 Memory (threads, links, evidence)。
- **信笺（The Letters）**：承载 Proactive/Outbox。折叠的光之纸张。
- **雾面帘（The Gauze Curtain）**：承载 Settings、DND、Privacy。拉下时模糊中景和远景。
- **呼吸光（The Breathing Light）**：承载 role_thinking 和 role_action。

### 2.4 角色泛化策略
剥离“圣女/审判者/叶筝”的具体叙事，提取其背后的“高洁、守候、注视、永恒”特质。将视觉元素抽象为“光、玻璃、水、冰”。这种中性的、具有神圣感但无具体宗教指向的“晶格温室”，能够完美兼容未来任何性格的长期伴侣角色（无论是温柔倾听者，还是冷静观察者），因为环境本身是包容且静谧的。

## 3. 信息架构与功能分层

### 3.1 总体层级
- **共鸣层（Resonance）**：核心交互。Chat、Thinking、Action。位于前景。
- **存在层（Existential）**：环境感知。Presence、State。弥漫于整个中景与光线。
- **回响层（Echo）**：记忆系统。Memory、Export。分布于空间四周的悬浮物。
- **生活层（Life）**：时间与日程。Proactive、Scheduling、Life Flow。依附于远景光窗与刻度。
- **边界层（Boundary）**：设置与限制。Settings、Notifications、DND。作为覆盖全局的雾面帘。
- **基石层（Foundation）**：系统审计。Trace、Ledger、Jobs。沉降于空间最底部的暗区。

### 3.3 Diegetic UI 入口策略
- **输入与对话**：无边框输入框，默认提示词为“触碰水面...”。光标是微弱的光晕。
- **未读信笺（Proactive）**：如果在 Outbox 中有数据，前景右下角会出现一个折叠的微光几何体（信笺），带有极缓慢的明暗呼吸，无数字角标。
- **记忆打捞（Memory）**：点击空间左侧悬浮的晶簇，晶簇会放大并移至屏幕中央（Overlay），背景被重度高斯模糊，晶簇展开显示 Threads。
- **设置与边界（Settings）**：鼠标悬停至屏幕最顶部，出现极细的磨砂玻璃质感指示条，向下拉动即可覆盖全屏，进入安静的设置模式。

### 3.4 信息密度策略
- **首屏绝对纯净**：只保留当前对话、输入水面、环境光影、以及必要的未读信笺。
- **Overlay (模糊浮层)**：用于 Memory 阅读、Diary 详情。使用强烈的 `backdrop-filter: blur(20px)`，让背景依然透出光感，但不干扰阅读。
- **Deep Drawer (深层抽屉)**：用于 Trace/Ledger。采用反向视觉（如背景变暗，出现冷蓝色的等宽字体网格），暗示进入了系统的“潜意识”或底层基石。

### 3.5 导航与返回模型
- **无“返回”按钮**：摒弃传统的 `< Back` 按钮。
- **空间缩放隐喻**：进入某个模块（如记忆晶体）时，该物件放大至中心，背景变暗/模糊。
- **退出机制**：点击主体内容之外的任意模糊区域（Lightbox 逻辑），或按下 `ESC` 键，物件缩小回到原位，完成“返回”。
- **单线程焦点**：同一时间只能打开一个深层空间（记忆或设置），避免多层浮层叠加导致 Z 轴混乱。
