# Luminous 前端设计指导大纲

## 1. 设计北极星

Luminous 是一个可长期停留的情感陪伴空间。用户首先感到“有人在”，其次才感到“可以完成一件事”。每个页面都应从陪伴关系出发，而不是从功能清单出发。

关键词：安静、克制、清澈、可信、可呼吸。

## 2. 首屏原则

- 人物主体是首屏第一视觉信号，必须清晰、完整并具有存在感。
- 首屏同时回答三件事：陪伴者在何种状态、刚刚说了什么、用户可在哪里开口。
- 回应内容在视觉和阅读顺序上位于输入之前；输入不能遮住最新回应。
- 首屏不是角色海报：人物、回应、环境和可行动入口需形成一个完整场景。

## 3. 空间隐喻与信息架构

使用“晶格温室”作为统一空间语言，让功能以环境物件出现：

| 空间物件 | 承载内容 | 体验要求 |
| --- | --- | --- |
| 人物与呼吸光 | 陪伴状态、存在感 | 只使用安全的 presence 与关系状态驱动环境。 |
| 水面 | 对话、输入、当前回应 | 不使用通用聊天气泡；让文字像在场景中浮现。 |
| 光窗 | Today、任务、提醒、日程 | 是“照看今天”，不是任务后台。 |
| 信笺 | 主动来信、outbox | 低打扰到达，不使用强制弹窗。 |
| 晶体 | 记忆 | 呈现可理解的记忆内容与隐私控制。 |
| 雾面帘 | 设置、通知、DND、隐私 | 用于收束注意力与保护边界。 |

功能入口应是空间中的自然物件或安静覆盖层，不是侧边栏、顶部工具条或卡片墙。

## 4. 视觉原则

- 以清冷白、冰蓝、深灰和少量暖光构成有层次的色彩关系；避免单色堆叠。
- 使用真实人物素材、纹理、透明度、景深和排版建立空间，不依赖渐变、装饰性光球或 bokeh。
- 页面分为远景、环境、中景人物、回应、输入、覆盖层，层级稳定且可解释。
- 文字优先可读。长文本应有稳定宽度、行高和安全留白，不能压在人物关键部位。
- 圆角只用于必要的控件、弹层和重复项目；不把整页内容包成浮动卡片。

## 5. 交互原则

- 陪伴优先于操作：默认界面保持安静，用户需要时才展开 Today、记忆、设置等次级空间。
- 所有真实写操作提供加载、成功、失败和重试；失败不丢失草稿。
- 影响现实生活的建议必须先预览、再由用户明确确认。
- 主动联系尊重通知设置、静默时段和 DND，不能制造焦虑或打断感。
- 动效只用于表达 presence、状态变化和空间过渡；减少动态偏好下应静止或显著减弱。

## 6. 数据与安全边界

- 视觉组件只消费前端展示模型；HTTP 响应在 adapter/service 层转换。
- 静态原型使用 fixture，不调用 API；联通阶段只替换 adapter，不推翻视觉结构。
- 普通界面只显示最终 `reply` 与安全 `presence`。
- 禁止显示或保存内部思考、prompt、ledger、trace、jobs、导出与调试数据。
- 关系、风险和情绪状态只能影响环境与语气，不能被做成数值评分、诊断或游戏化指标。

## 7. 响应式与可访问性

- 桌面与 390x844 手机均为一等目标；为人物、输入、回应和入口定义稳定尺寸与安全区。
- 手机键盘出现时，输入和最新回应必须同时可见。
- 使用语义化 HTML、原生按钮/输入、键盘导航和清晰的 `:focus-visible`。
- 不禁用用户缩放；实现 `prefers-reduced-motion`。
- 文本、控件和覆盖层不可出现遮挡、溢出或不可点击的重叠状态。

## 8. 分阶段交付

1. **静态体验原型**：完成主场景、默认情境和所有空间入口的视觉层级；用 fixture 驱动。
2. **核心陪伴联通**：接入状态与对话，验证安全字段、失败恢复与移动端输入。
3. **生活流联通**：接入 Today、任务、提醒和日程，以具体情境呈现操作。
4. **静默空间联通**：接入来信、记忆、通知与隐私。
5. **体验验收**：真实接口回归、桌面与手机截图、键盘与 reduced-motion 检查。

## 9. 每轮验收

- 不采纳实现者的自我声明；查看实际改动、真实请求和浏览器截图。
- 截图放在 `docs/front_design/acceptance/`，不要放入前端静态资源目录。
- 验收首先检查安全边界和内容可读性，其次检查视觉沉浸感，最后检查接口完整度。
