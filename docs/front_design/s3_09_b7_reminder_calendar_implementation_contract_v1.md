# S3 B7 提醒与日历实现契约 v1

> 状态：已实现并通过浏览器验收（2026-07-26）
> 批次：B7 Reminder / Calendar
> 依赖：B1–B6 已完成；Crystal Solarium v2 已通过视觉复核

## 1. 目标

B7 在既有“今日光影”对话框内补齐两种生活流资源：

- 提醒：以“提醒光尘”表达未来需要被轻声照看的时间点。
- 日历：以“窗框刻度”表达具有开始、结束或全天属性的时间区间。

它们是同一主场景中的子视图，不新增顶层入口、独立路由、月历大页或第二层模态框。

## 2. 视觉与交互约束

- 延续“晶格温室”的冷白、冰蓝、晨曦微光、物理雾面玻璃和纵深光窗。
- 提醒列表使用轻量粒子/微光标记，不使用红色告警、铃铛拟物或高压倒计时。
- 日历使用纵向窗框刻度，不实现月/周网格。
- 动效只辅助状态转移；`prefers-reduced-motion` 下必须稳定、无位移依赖。
- 桌面 1440×900、移动 390×844、软键盘抬起状态均需可用。
- 所有状态必须有文字语义，不能仅靠颜色、光晕或动画区分。

## 3. Reminder 功能边界

### 3.1 列表与详情

- 活跃区包含 `scheduled`、`due`、`snoozed`，按 `dueAt` 升序。
- 终态区包含 `completed`、`cancelled`、`expired`，默认折叠。
- 未知状态只读，不提供动作。
- 详情动作：完成、稍后提醒、取消、编辑。

### 3.2 编辑表单

- 必填：标题、提醒时间（`datetime-local`）。
- 可选：说明、重复规则（无/每日/每周）。
- `kind` 固定为 reminder，不向用户暴露选择器。
- 时区从浏览器推导，失败时回退 `UTC`。
- 编辑回填必须使用安全的本地时间格式化，禁止 `slice(0, 16)`。

### 3.3 写操作

- 完成：`POST /api/reminders/{key}/complete`，请求体 `{}`。
- 稍后提醒：用户必须输入确切的新时间；`POST .../snooze`，请求体 `{ due_at }`。
- 取消：`POST .../cancel`，请求体 `{}`；不能用 DELETE。
- 取消成功后保留为 `cancelled` 并移入终态区，不从列表删除。
- 编辑使用 PATCH，只发送实际变化字段。
- pending 期间禁用冲突动作；失败后保留用户输入的确切稍后时间。

## 4. Calendar 功能边界

### 4.1 列表与详情

- 纵向刻度按 `startsAt` 升序；同一天全天事件排在定时事件前。
- `deleted` 不进入可见列表；`unknown` 只读。
- 不调用单条 GET，详情使用已经加载的列表 ViewModel。

### 4.2 编辑表单

- 必填：标题、开始时间/日期。
- 可选：结束时间/日期；结束不得早于开始。
- `allDay` 是真实复选框；切换后在 date 与 datetime-local 控件间转换。
- 不提供 description 字段。
- 定时值严格本地时间往返验证后转换为 UTC `Z`。
- 全天值按本地午夜转换为 UTC `Z`，不自行假设结束日为排他边界。
- DST 不存在的本地时间必须拒绝，不能让浏览器静默归一化。

### 4.3 移出

- 使用详情内联确认，不弹第二个对话框。
- 文案：`从日历窗框移出这个刻度？` / `移出后，它将不再出现在当前日历列表中。`
- 调用 `DELETE /api/calendar-events/{key}`。
- 只有响应 ViewModel 的 `status === "deleted"` 时才从列表移除。
- 不承诺撤销、恢复或回收站。

## 5. 代码分工与模块

Codex 负责：

- `app-state.js`：安全 ViewModel、资源状态、编辑草稿、合法转换与恢复。
- `life-flow-controller.js`：时间校验、精确请求体、并发门、失败恢复。
- `reminder-view.js`、`calendar-view.js`：DOM 渲染与事件翻译，不直接访问 API。
- `main.js`、`today-view.js`、`index.html`：装配和现有今日子视图接入。
- 资源测试、控制器测试、浏览器验收、文档更新。

Gemini 负责：

- 两类资源在 Crystal Solarium v2 下的视觉层级、材质、排版、微交互和响应式 CSS 建议。
- 不负责业务状态机、API 调用、时间转换或最终 JS。
