# S5 安装、离线与更新体验设计 v1

> Gemini 负责视觉蓝图和截图审美复核；Codex 负责生命周期、状态、存储与安全边界。

## 1. 晶格温室延续

产品化状态不得成为系统通知条、红点或设置 Dashboard：

- 安装入口位于“隐私与边界”底部，作为低对比玻璃切面“安置温室”；
- 更新入口位于主场景右上晶格边缘，文案“窗外有新的晨光”；
- 恢复草稿只在输入面上方显示“昨夜的落笔还在。”；
- 离线不显示全页断网错误，保留模糊温室轮廓、人物存在感与空间入口；
- 图标使用深靛青底、冷白竖向光束与中心晶格切面，不使用人物、文字、宗教符号、太阳、叶片、聊天气泡或 AI 星芒。

## 2. 安装状态

| 状态 | 可见行为 |
| --- | --- |
| 浏览器不支持/不满足资格 | 安装区域完全隐藏 |
| `beforeinstallprompt` 就绪 | 显示“安置温室 / 留下光印” |
| 用户点击 | 调用一次浏览器原生 prompt |
| 拒绝/关闭 | 本次页面不再强迫出现 |
| `appinstalled` / standalone | 区域隐藏 |

最终诚实文案：

> 让这束光静止在你的设备里。离线时可看见温室的轮廓，回信仍需等待网络恢复。

## 3. 更新状态

- waiting 前完全隐藏；
- waiting 后显示“窗外有新的晨光”；
- 输入、发送或资源写入期间禁用；
- 点击后显示“正在推开窗...”，发送 `SKIP_WAITING`；
- `controllerchange` 后单次刷新；
- 不自动刷新，不使用 toast，不抢焦点。

## 4. 离线与恢复

- API 模式断网：隐藏对话流，避免静态示例文本伪装成缓存历史；
- 输入提示改为“当前没有风，信笺暂时无法寄出...”，发送禁用；
- 不清除符合 TTL 的未发送草稿；
- 恢复草稿时显示冷白微光提示，用户再次输入后隐藏；
- API 恢复后仍由现有 runtime 重新加载 `/api/state`，不从 CacheStorage 伪造业务状态。

## 5. 无障碍与响应式

- 安装、更新均为真实 `button`；
- 原生 checkbox/select/time 语义保留，视觉只包裹玻璃切面；
- `aria-live` 只用于草稿恢复和已有状态区，不重复广播装饰文案；
- 390×844 下安装区纵向排列，按钮满宽；
- reduced-motion 禁用产品化 transition；
- 离线移动端隐藏对话后，晶体入口与输入面之间保留大块呼吸空间。
