# Batch 2A-1：对话、凝露输入与 Presence 规格

## 1. 对话场总体模型

在「晶格温室」中，对话不再是堆叠的“信息块”，而是空间内流动的“光影文字”。

- **视觉层级：**
    - **当前片段 (Active Fragment)：** 位于视觉重心，高对比度（纯白），带轻微的文字阴影以保证在复杂背景下的可读性。
    - **短期历史 (Recent History)：** 向上滚动并逐渐淡化，透明度从 80% 降至 20%，伴随轻微的模糊（Backdrop-filter: blur），模拟在玻璃上消散的水汽。
    - **长期记忆 (Deep Memory)：** 默认隐藏。通过向上轻扫或点击特定“记忆锚点”触发，以纵深感极强的“回廊”形式展现，而非简单的垂直列表。
- **字幕替代气泡的逻辑：** 气泡是“容器”，强调界限；字幕是“投射”，强调内容与环境的融合。去掉头像、尖角、背景色块。对话通过文字的垂直错位（角色左对齐，用户右对齐，但均无底色框）来区分。
- **长回复处理：** 采用分段渐现逻辑。当回复超长时，文字按自然段落流式析出，而非一次性刷出。
- **回看机制：** 保持底部输入区不动，背景角色稍微后退（Scale 0.98），对话流向上平滑滚动，侧边出现极细的水晶刻度条。

## 2. 组件规格：SubtitleDialogue

| 维度 | 规格说明 |
| :--- | :--- |
| **职责** | 承载角色回复、内心独白、动作描述及用户输入。 |
| **DOM 建议** | `<section id="dialogue-container">` 内嵌 `<div class="msg-group">`。使用 `data-role` 区分 `companion` / `user`。 |
| **API 映射** | `reply` -> 主文本；`role_action` -> 括号内斜体/灰色文本；`role_thinking` -> 折叠的微光文本。 |
| **角色动作** | `role_action` 紧随回复内容，视觉上采用“纱质”半透明，如：*(轻轻放下茶杯)*。 |
| **内心独白** | `role_thinking` 默认以“…”或微弱光点显示，点击展开显示在回复上方，字体略小，带有冰蓝色调。 |
| **防线** | **禁止** 将 `system_thinking` 渲染到 DOM 中，甚至不应出现在 HTML 注释里。 |
| **加载状态** | 角色输入时，不显示“对方正在输入”，而是 PresenceHalo 进入 `thinking` 呼吸模式。 |
| **交互** | 长按文字可唤起“珍藏”（记忆）或“重塑”（重新生成）。 |
| **视觉细节** | 字体：优先衬线体 (Songti SC / Source Han Serif)；行高 1.8；字间距 0.05em。 |

## 3. 组件规格：AirInput (凝露输入)

- **视觉形态：** 底部中央悬浮的极简长条。无边框，仅有 `1px` 的极细白色半透明描边（0.1 alpha）。背景为 `saturate(180%) blur(20px)` 的玻璃材质。
- **多行处理：** 初始高度为单行，随内容增加向上生长，最高 5 行，超过后内部滚动。
- **发送逻辑：** 右侧一个极简的“↑”图标或“点亮”的光点。按下 Enter 发送，Shift+Enter 换行。
- **快捷提示 (Chips)：** `proactive` 字段驱动。提示词不以按钮形式出现，而是像漂浮在输入框上方的“气泡碎光”，点击即吸入输入框。
- **IME 处理：** 针对中文输入法，需监听 `compositionstart` 和 `compositionend`，确保在组词阶段不触发发送逻辑。
- **移动端：** 聚焦时，背景角色上移，输入框吸附于软键盘上方，保持 16px 的边距。
- **可访问性：** `role="textbox"`, `aria-label="与栖光对话"`, `tabindex="0"`。

## 4. 组件规格：PresenceHalo / Companion Presence

这是角色的“灵魂状态灯”，位于角色立绘/中心视觉区域的底层或周身。

| 状态 (State) | API 映射 (presence/state) | 视觉表现 (光晕、雾度、节奏) |
| :--- | :--- | :--- |
| **Calm (宁静)** | `calm` / 默认 | 极慢的冷白光呼吸，光晕半径 10%，雾度低。 |
| **Thinking (思索)** | `thinking` / `POST` 等待中 | 冰蓝色光点像雪花般向中心汇聚，节奏略快。 |
| **Warm (温情)** | `warm` / 关系度提升 | 浅金色光晕，边缘带有极轻微的扩散感。 |
| **Concerned (忧虑)** | `concerned` | 蓝紫色交替，光晕范围缩小，频率不规则。 |
| **Joy (喜悦)** | `joy` | 微光闪烁频率增加，伴随极细碎的晶体粒子溢出。 |
| **DND (静默)** | `dnd` | 极淡的灰蓝色，光晕几乎不可见，雾度增加。 |
| **Risk (风险)** | `risk` / 敏感词触发 | 极淡的珊瑚色（非正红），缓慢的脉冲式扩张。 |
| **Offline (断连)** | 失去心跳 / 404 | 光晕熄灭，角色立绘增加 20% 灰度与模糊。 |
| **Loading (初见)** | 初始进入 / `state-loading` | 全场雾化，光晕从中心向四周缓慢推开。 |

## 5. 核心流程：日常对话

1.  **输入阶段：** 用户点击 AirInput，输入框边缘泛起微光（Dew Effect）。
2.  **乐观显示：** 用户发送后，文字立即以 40% 透明度出现在对话区右侧，不等待 API 返回。
3.  **发送请求：** 调用 `POST /api/chat`。
4.  **状态切换：** PresenceHalo 切换至 `thinking` 模式；AirInput 进入 `disabled` 状态，发送图标变为微弱旋转的晶体。
5.  **返回处理：** 
    - 接收到 `reply`：用户消息变为 100% 不透明，角色消息从左侧流式析出。
    - 接收到 `presence`：PresenceHalo 立即平滑过渡到新状态。
    - 接收到 `memory`：在对话流侧边短暂闪烁一个“记忆晶片”图标。
6.  **错误处理：** 若失败，输入框震动，显示“光影失焦，稍后再试”，提供“重试”小字链接。
7.  **状态同步：** 每隔 30s 调用 `GET /api/state` 保持 Presence 同步。

## 6. 状态与错误矩阵

| 状态 ID | 场景 | 视觉表现 | 文案提示 | 可操作项 |
| :--- | :--- | :--- | :--- | :--- |
| `idle` | 待机 | 宁静光晕，角色微动 | 无 | 点击输入框 |
| `focused` | 准备输入 | 输入框描边增强 | “诉说你的心声...” | 输入文字 |
| `typing` | 输入中 | 输入框内出现流动的光丝 | 无 | 发送 |
| `sending` | 点击发送 | 消息向上传输特效 | 无 | 禁用输入 |
| `waiting` | 等待模型 | Presence 汇聚态 | 无 | 撤销(可选) |
| `replying` | 角色回复 | 逐字析出，对话区微光 | 无 | 停止生成 |
| `chat-error` | 网络中断 | 输入框泛红，文字模糊 | “连结中断了” | 重试 |
| `offline` | 无网络 | 全局去色，雾化增加 | “温室已断电” | 检查网络 |
| `state-loading`| 初始化 | 角色剪影渐现 | “正在唤醒...” | 无 |
| `state-error` | 状态同步失败 | Presence 变为灰色 | “感知模糊” | 刷新页面 |
| `empty-first-run`| 首次进入 | 只有一束顶光 | “在这里，时间是静止的” | 发起对话 |
| `thinking-avail` | 有内心独白 | 回复旁出现微弱“… ” | 无 | 点击展开 |
| `risk` | 触发敏感 | Presence 变为珊瑚色 | “这超出了我的理解” | 更改话题 |
| `dnd` | 角色疲劳/忙 | Presence 极淡 | “我想静静待一会儿” | 减少互动 |

## 7. Batch 2A-1 自检清单

1.  [ ] **去卡片化：** 确认没有任何带圆角背景色的消息方块。
2.  [ ] **沉浸感：** 角色立绘是否在对话流下方，且未被 UI 完全遮挡？
3.  [ ] **内心独白：** `role_thinking` 是否成功隐藏在微光交互后，而非直接显示？
4.  [ ] **系统屏蔽：** 确认 `system_thinking` 没有任何途径进入前端渲染。
5.  [ ] **输入反馈：** 中文输入法（IME）下，回车是否会误触发发送？
6.  [ ] **光晕动效：** PresenceHalo 的颜色过渡是否使用 `transition: all 2s ease` 确保平滑？
7.  [ ] **玻璃材质：** AirInput 的 `backdrop-filter` 在当前浏览器是否生效？
8.  [ ] **移动端：** 软键盘弹出时，SubtitleDialogue 是否自动向上滚动以避让？
9.  [ ] **API 完整性：** `POST /api/chat` 返回的所有字段（除 system_thinking）是否有对应的视觉落点？
10. [ ] **空态处理：** 首次进入没有对话时，界面是否依然具有“温室”的美感而非空白？
11. [ ] **动作渲染：** `role_action` 的括号斜体样式是否与正文有明显的视觉区分？
12. [ ] **性能：** 频繁的 `presence` 状态切换是否会导致 index.html 掉帧？（建议使用 CSS Variables 驱动动画）。
13. [ ] **对比度：** 在最亮的背景下，白色字幕是否依然清晰可读？（检查 text-shadow）。
14. [ ] **交互克制：** 所有的按钮和图标是否在不使用时自动半隐藏？
