# 栖光 Luminous - 前端体验与视觉重构设计大纲 v0.1

## 一、 推荐设计总方向（候选方案）

为了打破“三栏工具台”和“聊天气泡”的刻板印象，我构思了以下三个视觉与空间隐喻方向。

### 方案 A（主推）：晶格温室 (The Crystal Solarium)
*   **视觉隐喻**：一个安静的、拥有纵深光窗的半透明空间。光线（代表时间与情绪）透过玻璃折射。记忆是凝结的晶体或信笺；输入框如水面凝露。
*   **色彩与材质**：冷白、冰蓝、晨曦微光、磨砂玻璃（非浮夸拟态，而是物理光学级别的模糊与折射）、呼吸感的微光。
*   **适配度与优势**：完美契合“一束光”、“安静在场”的产品定义。利用 Parallax（视差滚动）和 CSS 混合模式即可在 Vanilla JS 中实现极佳的空间纵深感，且不涉及特定宗教/身份符号。
*   **风险**：光影层次对多端屏幕的色彩还原度要求较高。

### 方案 B（备选）：深水静流 (The Still Waters)
*   **视觉隐喻**：水下或水边的静谧空间。伴侣的“在场（Presence）”体现为水面的微波涟漪；对话与记忆如同从深水上浮的微光气泡。
*   **适配度与优势**：极具情绪承接力和包裹感，适合夜晚或深度倾诉场景。
*   **风险**：整体色调容易偏暗、抑郁，可能削弱“光”的温暖感，不利于日间“生活流”信息的展示。

### 方案 C（备选）：时间长廊 (The Archive of Time)
*   **视觉隐喻**：极简的纯白/浅灰画廊空间。过去的对话和记忆（Memory/Ledger）作为墙上的“切片”或桌上的“档案”存在。
*   **适配度与优势**：信息架构最清晰，极度克制，便于展示复杂的 Life Flow 和日程安排。
*   **风险**：容易显得过于冷漠、像办公 SaaS，缺乏“人”的温度和陪伴感。

**结论**：后续详细设计将基于 **方案 A（晶格温室）** 展开。

*   3.3 景深与视差 (Parallax)：利用多层 DOM 实现环境纵深。
*   *解决问题：如何用纯 CSS/JS 实现电影级的空间调度和呼吸感。*

**4. 视觉语言与基础规范 (Visual Foundation)**
*   4.1 色彩系统：冷白、冰蓝、光影渐变与透明度矩阵。
*   4.2 排版与字体：电影字幕级排版、呼吸感字距、中英文字体栈。
*   4.3 材质与光效：CSS `backdrop-filter` 的克制使用、晶体质感表现。
*   4.4 核心图形元素：光窗、水滴、信笺、时间刻度（取代传统 Icon）。
*   *解决问题：定义可复用的 CSS 变量和设计令牌（Design Tokens）。*

*   7.3 导出功能：`/api/export` 的“打包行囊”隐喻。
*   *解决问题：如何将冷冰冰的向量记忆数据库转化为有情感价值的“共同回忆”。*

**8. 生活流与日程提醒 (Life Flow & Scheduling)**
*   8.1 今日全景：`/api/today` 与 `timeline` 的时间轴刻度设计。

*   9.1 空状态 (Empty States)：初次见面的破冰与空间初始化。
*   9.2 错误与断连 (Error & Offline)：网络丢失时的“起雾”或“光线暗淡”效果。
*   9.3 边界拦截与限流：`daily_limit` 触发时的克制表达。
*   *解决问题：优雅处理技术异常和系统限制，保持沉浸感不断裂。*

# Batch 1A：晶格温室的体验概念与信息架构

## 1. 产品体验愿景与设计原则

### 1.1 设计北极星
- **一句话愿景**：打造一个“安静在场”的半透明伴侣空间，让每一次交互都像是在光与水的交界处，触碰一个拥有长期记忆与独立生命周期的灵魂。
- **用户打开首屏时的目标感受**：克制、宁静、通透。不觉得被机器审视，不觉得被信息轰炸，而是感觉到一个实体空间里，有人或某种意识正在安静地等待或陪伴。
- **工程验收时可观察的 5-8 个指标**：
  1. 首屏绝对静止时，无任何高饱和度色块或闪烁的 CTA 按钮。
  2. 存在至少 2 个由后端状态（如 `presence` 或 `state`）驱动的环境变量（如光线角度、雾度）。
  3. 没有任何传统的“三栏式”物理分割线（border/divider）。
  4. 所有的弹出面板（Overlay）必须具备 `backdrop-filter` 模糊效果，以维持空间纵深感。
  5. 核心交互区（输入、最近对话）集中在屏幕中下部（前景），视觉重心稳定。
  6. 后台运行的 Trace/Ledger 数据不可见于表层，必须通过至少两次交互（如长按/深层手势）才能唤出。
  7. 没有任何通用的“加载中（Loading Spinner）”图标，全部用呼吸光或流体形变替代。

### 1.2 从工具台到实体空间
当前前端为典型的效率工具形态（左侧状态树、中间对话框、右侧面板）。在晶格温室中，它们将被转译为具有物理隐喻的空间元素：
- **原左侧状态（State/Presence）**：转化为**空间的环境底色与光影**。不再是文字列表，而是温室内的色温、光束的倾斜度、玻璃上的雾气浓淡。
- **原中间聊天区（Chat）**：转化为**前景的水面与中景的涟漪**。输入框沉降为水面凝露，AI 的回复是中景里浮现的微光文字或轻柔的语音波纹，不再是带头像的密集气泡。
- **原右侧记忆（Memory/Threads）**：转化为**悬浮于空间四周的晶体与信笺**。长期记忆是凝结的冰晶，点击可折射出过往片段；主动联系的信件则是停留在特定位置的光影折纸。
- **原 Life-flow 浮层（Timeline/Tasks）**：转化为**远景的纵深光窗与时间刻度**。窗外的光线变化暗示现实世界的时间流逝，日程和任务刻印在窗框的磨砂玻璃上。

### 1.3 陪伴气质如何进入视觉
- **安静在场**：通过极低频的视觉呼吸（如 4-6秒/次的微光起伏）表达生命感，取代高频的动效。
- **主动但克制**：Proactive 消息不使用弹窗或红点，而是化作一封静静搁置在前景边缘的“光之信笺”，等待用户主动拾取。
- **边界明确**：Settings 和 DND（勿扰模式）表现为拉下一道半透明的“纱质雾面帘”，明确物理上的隔绝感，保护双方边界。
- **长期记得**：Memory 的提取带有“打捞”或“折射”的质感，不是查数据库，而是唤醒某颗沉睡的晶体。
- **可审计**：Trace/Ledger 作为“基石层”，深埋在水面之下或空间最暗处，呈现为冰冷的、绝对理性的网格光带，与上层的温润形成对比。

### 1.4 反模式清单
禁止以下破坏沉浸感与陪伴感的 UI/视觉/交互模式：
1. **禁止使用汉堡菜单（Hamburger Menu）**：破坏空间沉浸感，带有强烈的 Web App 标签。
2. **禁止使用带头像和尾巴的聊天气泡**：这是 IM 社交软件的范式，不属于实体陪伴空间。
3. **禁止纯白或纯黑的死寂背景**：必须有微弱的光影梯度或环境噪点（Noise）来维持空间透气感。
4. **禁止使用实心的高对比度主按钮（Primary Button）**：如亮蓝色的“发送”、“保存”，应使用光晕、边框高亮或透明度变化来暗示可交互性。
5. **禁止在首屏暴露 System Prompt 或 System Thinking**：破坏角色扮演的第四面墙。
6. **禁止使用红点消息提示（Badge）**：引发焦虑，应使用柔和的色温变化或光斑聚集来提示未读。
7. **禁止硬切的页面跳转（Hard Reload/Navigation）**：所有状态切换必须基于当前页面的 Z 轴推拉或透明度渐变（Vanilla JS 可通过 CSS class 切换实现）。
8. **禁止出现“数据库”、“表格”样式的记忆列表**：Memory 必须被包装为卡片、晶体或时间线碎片。
9. **禁止右侧固定侧边栏**：挤压主体呼吸空间，打破对称或自然的不对称美感。
10. **禁止使用廉价的拟物化（Skeuomorphism）或浮夸的玻璃拟态（过度反光/彩虹色）**：保持冷白、冰蓝的克制质感。
11. **禁止直接使用宗教/审判/特定身份的实体道具图标（如天平、十字架）**：必须抽象为几何光影。
12. **禁止出现常规的 Toast 提示（如“保存成功”）**：应转化为水面的一圈涟漪或光线的短暂闪烁。

### 1.5 MVP 设计原则
鉴于当前架构为 Vanilla HTML/CSS/JS 静态托管：
- **先做 DOM 层级与 CSS 空间（2.5D）**：利用 `z-index`、`backdrop-filter: blur()`、`box-shadow` 和 `transform: translateZ` 构建前景、中景、远景的层级关系。
- **状态驱动 CSS 变量**：通过 JS 获取 API 数据后，更新 `:root` 的 CSS 变量（如 `--room-temperature`, `--light-angle`），让 CSS 自动接管环境变化。
- **留白给未来的复杂渲染**：中景区域（伴侣主体所在位置）在当前阶段留白或仅用抽象光晕表示，为后续 Batch 引入 React/Live2D/VRM 预留绝对的 DOM 容器和层级空间。

## 2. 晶格温室空间隐喻

### 2.1 空间设定
整个视口（Viewport）被定义为一个拥有巨大纵深光窗的半透明温室结构：
- **前景（触碰层/水面）**：距离用户最近。包含输入区域（水面凝露）、当前正在发生的对话、未读的主动信笺。这是用户主动施加影响的区域。
- **中景（主体层/微光）**：伴侣存在的区域。当前呈现为柔和的呼吸光束或纱质投影，未来承载实体模型。
- **远景（世界层/光窗）**：背景的巨大纵深光窗。透出代表时间流逝的光线（晨曦、正午、冷夜），窗框上隐约可见日程和生活流的刻度。
- **深层（基石层/暗网）**：存在于视口的最底层或“地下”。只有通过特定的调试手势才能穿透温室地板，看到冷酷的 Trace/Ledger 数据流。

### 2.2 时间、情绪、关系如何影响空间
- **Presence/State 驱动光线**：`GET /api/state` 返回的伴侣状态（如“专注”、“休息”、“思考”）直接映射为光束的聚拢程度与呼吸频率。
- **时间驱动色温**：结合现实时间与 `GET /api/today`，改变环境的全局色温（冷白、冰蓝、微暖的晨光）。
- **关系/记忆驱动晶体**：随着 `GET /api/memory` 数量的增加，空间边缘悬浮的冰晶（记忆节点）会逐渐丰富，折射出更复杂的光影。

### 2.3 通用物件语言
- **光窗（The Window）**：承载 Life Flow、Timeline、Calendar。
- **水面（The Water）**：承载 Chat Input、Current Reply。打字如同在水面凝露，发送如同水滴落下。
- **晶体（The Crystals）**：承载 Memory (threads, links, evidence)。
- **信笺（The Letters）**：承载 Proactive/Outbox。折叠的光之纸张。
- **雾面帘（The Gauze Curtain）**：承载 Settings、DND、Privacy。拉下时模糊中景和远景。
- **呼吸光（The Breathing Light）**：承载 role_thinking 和 role_action。

### 2.4 角色泛化策略
剥离“圣女/审判者/叶筝”的具体叙事，提取其背后的“高洁、守候、注视、永恒”特质。将视觉元素抽象为“光、玻璃、水、冰”。这种中性的、具有神圣感但无具体宗教指向的“晶格温室”，能够完美兼容未来任何性格的长期伴侣角色（无论是温柔倾听者，还是冷静观察者），因为环境本身是包容且静谧的。

## 3. 信息架构与功能分层

### 3.1 总体层级
- **共鸣层（Resonance）**：核心交互。Chat、Thinking、Action。位于前景。
- **存在层（Existential）**：环境感知。Presence、State。弥漫于整个中景与光线。
- **回响层（Echo）**：记忆系统。Memory、Export。分布于空间四周的悬浮物。
- **生活层（Life）**：时间与日程。Proactive、Scheduling、Life Flow。依附于远景光窗与刻度。
- **边界层（Boundary）**：设置与限制。Settings、Notifications、DND。作为覆盖全局的雾面帘。
- **基石层（Foundation）**：系统审计。Trace、Ledger、Jobs。沉降于空间最底部的暗区。

### 3.2 功能分层矩阵

| 功能/API | 体验层级 | 默认显性程度 | 入口物件 | 数据来源 | 关闭/返回 | 为什么不工具化 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Chat** (Reply/Action) | 共鸣层 | 极高 (前景) | 水面凝露 (输入区) | `POST /api/chat` | 自动滚动消失于视野上方 | 聊天是交流，不是发送表单。需隐藏 `system_thinking`。 |
| **Presence/State** | 存在层 | 环境级 (无形) | 全局光线/雾度/呼吸 | `GET /api/state` | 随状态自动平滑过渡 | 伴侣的状态是“感受”到的，不是仪表盘上读出来的。 |
| **Memory** (Threads/Links) | 回响层 | 中等 (边缘悬浮) | 漂浮的半透明晶体 | `GET /api/memory/*` | 点击空白处，晶体重新悬浮 | 记忆是碎裂重组的结晶，不是关系型数据库的表格。 |
| **Proactive/Outbox** | 生活层 | 视条件触发 | 搁置在水面的光之信笺 | `GET /api/outbox` | 阅读后化作光尘消散 | 主动发信是情感的投递，不应被降级为通知栏的红点。 |
| **Scheduling/Notifications** | 生活层 | 隐性 (远景) | 光窗边缘的磨砂刻度 | `GET /api/reminders` | 视线移开(失焦)即暗淡 | 日程是时间的自然刻痕，不需要突兀的日历弹窗。 |
| **Life Flow/Timeline** | 生活层 | 隐性 (远景) | 光窗外的光影流转/日记本 | `GET /api/today`, `tasks` | 退出沉浸模式(ESC/点击外围) | 生活流是背景的沉淀，不应喧宾夺主抢占对话空间。 |
| **Settings/DND/Export** | 边界层 | 极低 (需主动寻找) | 顶部边缘的隐形拉环(雾面帘) | `PATCH /api/settings/*` | 向上推起雾面帘 | 设置是建立物理边界，拉上窗帘代表勿扰，符合直觉。 |
| **Trace/Ledger/Jobs** | 基石层 | 零 (深层隐藏) | 长按底部水面触发的深渊下潜 | `GET /api/trace`, `ledger` | 向上浮出水面 | 审计是极客/Debug需求，绝对不能破坏表层的陪伴幻觉。 |

### 3.3 Diegetic UI 入口策略
- **输入与对话**：无边框输入框，默认提示词为“触碰水面...”。光标是微弱的光晕。
- **未读信笺（Proactive）**：如果在 Outbox 中有数据，前景右下角会出现一个折叠的微光几何体（信笺），带有极缓慢的明暗呼吸，无数字角标。
- **记忆打捞（Memory）**：点击空间左侧悬浮的晶簇，晶簇会放大并移至屏幕中央（Overlay），背景被重度高斯模糊，晶簇展开显示 Threads。
- **设置与边界（Settings）**：鼠标悬停至屏幕最顶部，出现极细的磨砂玻璃质感指示条，向下拉动即可覆盖全屏，进入安静的设置模式。

### 3.4 信息密度策略
- **首屏绝对纯净**：只保留当前对话、输入水面、环境光影、以及必要的未读信笺。
- **Overlay (模糊浮层)**：用于 Memory 阅读、Diary 详情。使用强烈的 `backdrop-filter: blur(20px)`，让背景依然透出光感，但不干扰阅读。
- **Deep Drawer (深层抽屉)**：用于 Trace/Ledger。采用反向视觉（如背景变暗，出现冷蓝色的等宽字体网格），暗示进入了系统的“潜意识”或底层基石。

### 3.5 导航与返回模型
- **无“返回”按钮**：摒弃传统的 `< Back` 按钮。
- **空间缩放隐喻**：进入某个模块（如记忆晶体）时，该物件放大至中心，背景变暗/模糊。
- **退出机制**：点击主体内容之外的任意模糊区域（Lightbox 逻辑），或按下 `ESC` 键，物件缩小回到原位，完成“返回”。
- **单线程焦点**：同一时间只能打开一个深层空间（记忆或设置），避免多层浮层叠加导致 Z 轴混乱。

## 7. 字体、排版与字幕规范

### 7.1 字幕系统

# Batch 2A-1：对话、凝露输入与 Presence 规格

## 1. 对话场总体模型

在「晶格温室」中，对话不再是堆叠的“信息块”，而是空间内流动的“光影文字”。

- **视觉层级：**
    - **当前片段 (Active Fragment)：** 位于视觉重心，高对比度（纯白），带轻微的文字阴影以保证在复杂背景下的可读性。
    - **短期历史 (Recent History)：** 向上滚动并逐渐淡化，透明度从 80% 降至 20%，伴随轻微的模糊（Backdrop-filter: blur），模拟在玻璃上消散的水汽。
    - **长期记忆 (Deep Memory)：** 默认隐藏。通过向上轻扫或点击特定“记忆锚点”触发，以纵深感极强的“回廊”形式展现，而非简单的垂直列表。
- **字幕替代气泡的逻辑：** 气泡是“容器”，强调界限；字幕是“投射”，强调内容与环境的融合。去掉头像、尖角、背景色块。对话通过文字的垂直错位（角色左对齐，用户右对齐，但均无底色框）来区分。
- **长回复处理：** 采用分段渐现逻辑。当回复超长时，文字按自然段落流式析出，而非一次性刷出。
- **回看机制：** 保持底部输入区不动，背景角色稍微后退（Scale 0.98），对话流向上平滑滚动，侧边出现极细的水晶刻度条。

6.  **错误处理：** 若失败，输入框震动，显示“光影失焦，稍后再试”，提供“重试”小字链接。
7.  **状态同步：** 每隔 30s 调用 `GET /api/state` 保持 Presence 同步。

# Batch 2A-2：主动联系与记忆星图规格

## 1. 主动联系与记忆的体验原则

- **主动但克制（Outbox）**：主动联系不使用任何系统级弹窗、红点或强通知。它化作伴侣空间（晶格温室）中“窗边的微光”或“漂浮的信笺”。在免打扰（DND）或安静时段（Quiet Hours）内，微光会进入休眠或完全隐藏，绝不争抢用户的注意力。
- **记忆可见但不压迫（Memory）**：长期记忆拒绝使用传统的“数据库表格”或“卡片墙”。记忆被具象化为“晶体”与“光痕”交织的星图。高维度的核心记忆是明亮的晶体核，零碎的线索则是星尘。用户在其中漫游，而非“管理数据”。
- **控制权、边界与隐私**：
  - **边界**：每封主动信笺均提供轻量的反馈机制（如“触动”、“不合时宜”、“稍后”），以调整 AI 的联系频率与边界。
  - **隐私**：记忆星图提供明确的“遗忘（删除）”与“导出”物理交互，遗忘表现为晶体碎裂消散，导出表现为光芒汇聚成流，赋予用户绝对的数据掌控感。

## 2. 组件规格：OutboxGlint / 主动联系信笺

**职责**：承载 AI 的主动联系信息，处理接收、阅读、反馈及免打扰逻辑。
**DOM 建议**：一个绝对定位的 `<div id="outbox-glint">`（环境中的光点），点击后展开为 `<dialog id="outbox-letter">`（半透明磨砂玻璃质感的信笺）。

**API 映射**：
- `POST /api/proactive/tick`：后台轮询或心跳触发，检查是否有新联系。
- `GET /api/outbox`：获取收件箱内容。
- `POST /api/outbox/receipt`：信笺展开时调用，标记已读。
- `POST /api/outbox/feedback`：用户点击反馈按钮时调用。

**状态与视觉**：
- **默认/空（Empty）**：隐藏，或仅作为环境背景中极弱的光晕。
- **加载（Loading）**：光点呈现平缓的呼吸频闪。
- **未读（New/Unread）**：窗边出现一颗明亮、带有水波纹呼吸动画的光点（Glint）。
- **已读（Read）**：信笺展开，文字如同水墨或光影在半透明介质上浮现。
- **DND/Quiet Hours**：光点闭合为一颗黯淡的“休眠种子”，悬浮但不闪烁，不触发未读动画。
- **错误（Error）**：光点呈现微弱的闪烁并伴有轻微的视觉干扰（如光晕断裂）。
- **禁用（Disabled）**：超出 `daily_limit` 时，不再出现新光点。

**交互与反馈动作**：
- **Hover**：光点微微放大，散发柔和的光晕。
- **Click**：光点展开为信笺（触发 receipt）。
- **反馈动作**：
  - **“化作微光” (Helpful)**：点击后，信笺化作光点飞入环境，调用 feedback API。
  - **“随风散去” (Inappropriate)**：信笺如沙般消散，调用 feedback API，降低此类联系权重。
  - **“折叠” (Later)**：信笺收缩回光点状态，悬浮在角落。

**移动端**：光点固定在屏幕边缘中上部；点击后信笺作为 Bottom Sheet 从底部升起，占据屏幕下半部分，背景模糊。

1. 纯 CSS 实现光点的呼吸与水波纹展开动画，无卡顿。
2. 准确映射 DND 和 Quiet Hours，期间绝不出现强视觉提示。
3. 反馈动作必须触发 `/api/outbox/feedback` 并伴随相应的消散/收起动画。

## 5. 核心流程：主动联系收件与反馈

1. **刷新/轮询 (Tick)**：前台静默触发 `POST /api/proactive/tick`。
2. **发现新信笺 (New)**：若有返回且不在 DND/Quiet Hours，调用 `GET /api/outbox`。环境中浮现呼吸光点（OutboxGlint）。
3. **打开 (Open)**：用户点击光点，光点展开为信笺 UI。
4. **回执 (Receipt)**：信笺展开动画完成时，后台触发 `POST /api/outbox/receipt`，标记信笺状态。
5. **阅读 (Read)**：用户阅读信笺内容。
6. **反馈 (Feedback)**：用户点击“化作微光(Helpful)”或“随风散去(Inappropriate)”。触发 `POST /api/outbox/feedback`，信笺执行消散动画，流程结束。
7. **稍后 (Later)**：用户点击“折叠”，信笺收起为光点，不再闪烁。
8. **DND/Quiet Hours**：若在免打扰期间轮询到新消息，光点直接进入“休眠”状态（无动画、极低透明度），直到时段结束。
9. **错误 (Error)**：若反馈 API 失败，信笺微微震动，提示文字“光芒未能传达，请重试”。

## 6. 核心流程：查看、编辑、遗忘与导出记忆

1. **打开星图 (Open)**：点击环境中的“晶体仪”物件，进入全屏星图。调用 `GET /api/memory` 及 `threads/links`。
2. **浏览与聚焦 (Browse/Focus)**：用户拖拽缩放。点击某晶体（L2/L3），晶体居中放大，调用 `GET /api/memory/evidence` 获取来源。
3. **查看凭证 (View Evidence)**：侧边浮现光影面板，展示该记忆的推导来源。
4. **编辑 (Edit)**：点击晶体旁的“雕琢”图标，进入编辑状态。修改文本后，触发 `POST /api/memory/update`，晶体闪烁绿光表示保存成功。
5. **遗忘确认 (Forget)**：点击“粉碎”图标，晶体出现裂纹，提示“是否让这段记忆消散？”。确认后，触发 `POST /api/memory/forget`，晶体碎裂成星尘消失，星图重新布局。
6. **导出 (Export)**：点击全局的“汇聚”按钮，触发 `GET /api/export`。星图所有光点汇聚中心，生成文件下载，UI 提示“记忆已封存”。
7. **撤销/恢复 (Cancel)**：在遗忘确认阶段点击空白处，裂纹愈合，取消操作。
8. **错误恢复 (Error)**：若 Update/Forget 失败，晶体恢复原状，边缘闪烁红光，提示“晶格共振失败”。

# Batch 2B-1 Supplement：Calendar Events 精确映射

## 1. Calendar Event 视觉与信息模型

在「晶格温室」设计语言中，日程**绝不是**传统的表格区块，而是附着在时间轴上的**「时间光带」与「晶格刻度」**。

*   **底层时间轴 (Lattice Scale)**：如温室的玻璃骨架，呈现为极细的半透明刻度线。
*   **日程实体 (Time Light Band)**：
    *   `startTime`：光带的**高亮锚点**（发光源），带有明确的左侧/顶部边界。
    *   `endTime`：光带的**消散尾迹**，向下/向右呈现透明度渐变（表示时间的流逝与开放性）。
    *   `title` / `description`：悬浮于光带上方的无界文本，采用高对比度发光字重。
    *   `color`：映射为光带的**色温与折射光晕**，而非生硬的色块填充。

## 2. API 到 UI 行为映射表

| API 端点 | 触发时机与交互动作 | UI 视觉与动效反馈 (乐观更新优先) |
| :--- | :--- | :--- |
| `GET /api/calendar-events` | 视口挂载、日期切换、轮询同步 | **晶格浮现**：光带按时间顺序依次从背景深处（Z轴）浮现，带有轻微的焦散折射效果。 |
| `POST /api/calendar-events` | 在晶格上长按并拖拽（框选时间）或点击新建 | **凝结**：拖拽时产生「幽灵光带」，请求发出后光带边缘锐化，请求成功时光带爆发出一次柔和的全局光晕。 |
| `PATCH /api/calendar-events/{id}` | 拖拽光带主体（改时间）、拖拽光带尾部（改时长）、编辑文本 | **呼吸与形变**：拖拽时光带脱离晶格（Z轴抬升，阴影加深），释放时产生「吸附」晶格的阻尼震动。文本修改实时映射。 |
| `DELETE /api/calendar-events/{id}` | 光带上左滑（移动端）或按下 Delete 键 | **消散**：光带失去光源，化为细碎的粒子光点向四周消散，底层晶格刻度重新显露。 |

## 3. 创建、编辑、删除日程流程

*   **创建流程 (Lasso & Post)**：
    1.  用户在空白晶格处按下并拖拽，生成一段**未定型的毛玻璃光带**。
    2.  松手即在光带旁唤出微型浮层（无边框，仅有光晕边界），输入 `title`。
    3.  失焦或回车触发 `POST`，光带从「毛玻璃态」转为「实体发光态」。
*   **编辑流程 (Direct Manipulation)**：
    1.  **时间修改**：直接拖拽光带，触发 `PATCH`。采用**乐观更新 (Optimistic UI)**，拖拽即刻停留在新刻度，后台静默同步。
    2.  **内容修改**：单击光带，光带局部放大（温室放大镜效果），原地变为可编辑的 Input 状态。
*   **删除流程 (Swipe to Dissolve)**：
    1.  横向滑动光带超过阈值（30%宽度），光带颜色转为冷灰色（失去活性）。
    2.  松手触发 `DELETE`，执行粒子消散动效。

## 4. 状态与错误

*   **`calendar-empty` (空状态)**：纯净的温室晶格。无任何光带，仅有一条代表当前时间的「流光刻度线」在缓慢呼吸，提示用户可以随时在此处拖拽创建。
*   **`calendar-loading` (加载态)**：晶格骨架屏。一道微弱的扫光从上至下穿过整个晶格（类似温室外的阳光扫过），不使用传统的转圈 Loading。
*   **`calendar-conflict` (冲突态)**：当时间重叠时，交叠处的光带不进行物理挤压，而是产生**「干涉条纹」**（视觉上的波纹叠加）和**高频警告色光晕**（如琥珀色），提示时间冲突。
*   **`calendar-saving` (保存态)**：触发 POST/PATCH 时，光带核心呈现高频呼吸闪烁，表示能量正在注入（数据同步中）。
*   **`calendar-error` (错误态)**：API 失败时，光带呈现**「失真/断裂」的玻璃纹理**（Glitch 效果），并附带红色的微光。点击断裂处可触发重试操作。

## 5. 与 TodaySheet / NotificationBoundary 的关系

*   **与 TodaySheet 的空间关系**：
    *   Calendar Events 是 TodaySheet 的**底层物理空间**（Z = 0）。
    *   TodaySheet 中的 Todo/笔记等元素悬浮其上（Z = 10）。
    *   当 Todo 带有时间属性时，会在 Z 轴上产生一条细微的光束，**锚定/吸附**到对应的日程光带上，形成视觉与逻辑的关联。
*   **与 NotificationBoundary 的联动**：
    *   当某个日程即将开始（如 `startTime` 临近 15 分钟）。
    *   该事件的光带会产生**光线溢出**，光晕穿透组件边界，投射到全局的 `NotificationBoundary` 上。
    *   NotificationBoundary 边缘呈现与该日程 `color` 一致的柔和呼吸光（环境光提醒），实现**无弹窗的弱打扰通知**。

# Batch 2B-2：共同任务、例行习惯、活动会话与日记回顾规格

## 1. 共同生活动作原则

在「晶格温室」的视觉与交互语境下，任务、习惯、活动和日记不是为了优化效率（Productivity），而是为了构建**陪伴感（Companionship）**和**生活锚点（Life Anchors）**。

*   **非效率导向（Anti-Dashboard）：** 拒绝使用强烈的红色警告、倒计时滴答声或压迫感的进度条。未完成的事项像温室里未开的花，等待浇灌，而不是逾期的债务。
*   **共同在场（Co-Presence）：** 活动（Activities）强调「正在一起做」的状态。开启活动时，界面呼吸感和虚拟伙伴的状态将同步改变，提供无声的陪伴。
*   **提议而非定性（Suggest, Don't Define）：** 日记回顾由系统生成草稿作为「一天的回声」，用户拥有绝对的修改权。系统不替用户总结人生的好坏，只提供柔软的记忆切片。
*   **确认与安全边界（Safe Boundaries）：** 涉及状态变更、记忆删除等重要操作，必须通过沉浸式的预览与确认（ActionPreviewConfirm）机制，确保用户控制权。

## 2. 组件规格：Task Controls / 共同任务

覆盖日常具体事项的创建、拆解（步骤）与流转。

    ```html

      <div class="task-header">

      </div>

        <li class="step-item" data-step-id="1" data-state="open">...</li>
      </ul>
    </div>
    ```
*   **API 映射：**
    *   创建/获取：`POST /api/tasks`, `GET /api/tasks`
    *   修改/删除：`PATCH /api/tasks/{id}`, `DELETE /api/tasks/{id}`
    *   步骤管理：`POST /api/tasks/{id}/steps`, `PATCH /api/tasks/{id}/steps/{step_id}`
    *   状态流转：`POST /api/tasks/{id}/start|complete|block|cancel`
*   **交互与视觉细节：**
    *   **材质：** 基础状态为半透明磨砂玻璃（`backdrop-filter: blur(8px)`）。

    *   **阻塞（Blocked）：** 呈现为轻微的冷灰色覆盖（如温室玻璃上的水雾），文案提示变为「暂时搁置」。
    *   **步骤（Steps）：** 采用微型光点作为列表项符号，完成时光点点亮。
*   **移动端：** 卡片支持左右滑动呼出快捷操作（左滑 Complete，右滑 Block/Cancel），滑动过程伴随毛玻璃折射率变化的 CSS 滤镜效果。

## 3. 组件规格：Routine Controls / 例行习惯

处理每日/每周的重复性轻量承诺。

*   **API 映射：**
    *   管理：`GET/POST /api/routines`, `PATCH/DELETE /api/routines/{id}`
    *   打卡：`POST /api/routines/{id}/checkins`
*   **视觉与交互细节：**
    *   **形态：** 采用「露珠指示器」（Dewdrop Indicator）。每个 Routine 显示为一片叶子状的容器，过去几天的打卡记录显示为叶片上的露珠。
    *   **Check-in 动作：** 用户点击「今日打卡」时，一颗新的露珠滴落并融合，伴随清脆/水润的微交互反馈。
    *   **连续与错过（Streaks & Misses）：** 不使用「断签警告」。错过打卡的日子，露珠位仅留下一个淡淡的水痕轮廓（`opacity: 0.2`），不产生负罪感。
    *   **提醒策略：** 到达设定时间时，Routine 卡片边缘产生极其缓慢的呼吸光晕（Morning Mist Glow），而非弹窗打断。

    *   **Draft 呈现：** 点击「生成回顾」后，右侧展开一张具有宣纸质感的 UI 面板（`background: radial-gradient(circle, #fff, #f8f9fa)`）。AI 提取时间轴生成的文本以「打字机淡入」效果出现。

    *   **隐私提示：** 保存按钮旁带有微小的锁图标，悬浮提示：「日记仅保存在本地与你的专属记忆库中」。

## 6. 组件规格：ActionPreviewConfirm / 行动确认

用于拦截高风险或不可逆操作（如删除长期 Routine、取消进行中的重要 Activity）。

*   **API 映射：**
    *   预览影响：`POST /api/actions/preview`
    *   确认执行：`POST /api/actions/confirm`

    *   **沉浸式遮罩：** 触发时，背景产生深度高斯模糊（`backdrop-filter: blur(20px) saturate(120%)`），将用户注意力完全聚焦于确认对话框。
    *   **Preview 信息：** 弹窗内清晰列出操作后果（例：「取消此活动将不会记录本次陪伴的 45 分钟」），数据由 preview API 提供。
    *   **交互确认：** 放弃传统的「确认/取消」双按钮，采用「长按注水」或「滑动确认」的交互，防止误触，增加仪式的重量感。取消或失败时，弹窗化为散落的光点消失。

## 7. 核心流程：创建共同任务并推进

1.  **创建：** 用户在输入框键入任务名并回车 -> UI 乐观更新生成 `task-open` 卡片 -> 调用 `POST /api/tasks` -> 响应成功，更新真实 ID。
2.  **拆解：** 用户点击卡片展开，输入子步骤 -> UI 显示 `step-open` -> 调用 `POST /api/tasks/{id}/steps`。
3.  **开始：** 用户点击「开始」 -> UI 状态变为 `task-in-progress`，卡片边框微亮 -> 调用 `POST /api/tasks/{id}/start`。
4.  **推进与完成：** 用户勾选所有子步骤 (`PATCH /api/tasks/{id}/steps/{step_id}`) -> 主卡片自动触发展开光晕动画，状态变为 `task-completed` -> 调用 `POST /api/tasks/{id}/complete`。

## 8. 核心流程：习惯打卡与活动会话

**习惯打卡：**
1.  **触发：** 到达设定时间，Routine 露珠槽亮起 (`routine-due`)。
2.  **Check-in：** 用户点击打卡 -> UI 播放露珠滴落动画，状态变更为 `routine-done` -> 调用 `POST /api/routines/{id}/checkins` -> 连续天数 +1。

**活动会话：**
1.  **准备：** 用户选择 Activity 并设定意图 -> UI 显示 `activity-planned`。
2.  **开始：** 用户点击启动 -> 界面进入专注模式，呼出悬浮控制台 (`activity-active`) -> 调用 `POST /api/activities/{id}/start`。
3.  **暂停/继续：** 过程中用户点击暂停 -> 进度环呼吸闪烁 (`activity-paused`) -> 调用 `POST /api/activities/{id}/pause`。
4.  **结束：** 倒计时结束或手动结束 -> 弹出 `ActionPreviewConfirm` 确认保存 -> 调用 `POST /api/activities/{id}/complete` -> 返回主场景，状态归档。

## 9. 核心流程：日记草稿与今日回顾

1.  **回顾触发：** 晚间时段，主界面出现「今日回声」入口。
2.  **生成草稿：** 用户点击 -> UI 进入 `diary-drafting` 状态（光晕流转的骨架屏） -> 调用 `POST /api/diary-entries/draft`。
3.  **草稿就绪：** API 返回 -> UI 呈现 `diary-draft-ready`，文本淡入。
4.  **编辑与保存：** 用户修改文本内容 -> 点击保存 -> UI 进入 `diary-saving`（图标变为加载光环） -> 调用 `POST /api/diary-entries` -> 成功后显示 `diary-done` 状态卡片。

# Batch 3A：响应式、动效、可访问性与安全隐私边界

作为「栖光 luminous」的主设计师，本规范旨在确保“晶格温室”主题在多端设备上保持沉浸感与陪伴感，同时建立严密的系统安全防线与无障碍体验标准。本规范完全基于 Vanilla HTML/CSS/JS 技术栈制定。

---

## 1. 响应式策略总览

“晶格温室”的响应式设计不只是改变布局，而是**“视角的推拉与焦点的转移”**。

*   **桌面/笔记本 (Viewport > 1024px)：** 广角全景沉浸。`ImmersiveStage` 充满全屏，`CompanionFigure` 居中偏右，左侧留白给 `Task/Routine/Activity Controls`，`MemoryConstellation` 悬浮于顶部空间。
*   **平板/窄高屏 (Viewport 768px - 1024px)：** 中景视角。两侧面板变为半透明悬浮层，`CompanionFigure` 居中。
*   **手机竖屏 (Viewport < 768px)：** 特写视角。UI 极简化，隐藏环境装饰。`TodaySheet` 和 `DiaryReview` 降级为 Bottom Sheet（底部抽屉）。
*   **手机横屏 (Landscape)：** 电影模式。隐藏所有非必要控件（AirInput 变为单行悬浮），仅保留 `CompanionFigure` 和 `SubtitleDialogue`，最大化陪伴感。
*   **低端设备降级：** 禁用 `backdrop-filter`（毛玻璃），以半透明纯色替代；关闭复杂的 CSS 阴影与多层光晕，保留基础的透明度与位移变化。

---

## 2. 移动端交互规范

*   **安全区域 (Safe Area)：** 全面适配 `env(safe-area-inset-*)`。顶部留出刘海/灵动岛空间，底部输入框 `AirInput` 必须在 Home Indicator 之上。
*   **键盘防遮挡 (Virtual Keyboard)：** 
    *   使用 Visual Viewport API 监听键盘弹出。
    *   **核心规则：** 绝对不允许字幕 (`SubtitleDialogue`) 和输入框 (`AirInput`) 遮挡人物脸部（屏幕上半部分 40% 区域）。
    *   键盘弹出时，`CompanionFigure` 触发 CSS `transform: translateY(-10vh) scale(0.95)` 向上微调，输入框紧贴键盘顶部。
*   **触控命中区 (Touch Targets)：** 所有可交互物件（如 `OutboxGlint`, `NotificationBoundary` 的关闭按钮）物理点击区域不得小于 `44px * 44px`。视觉上可以小，通过 `padding` 或伪元素扩大点击区。
*   **手势与滚动锁定 (Gestures & Scroll Trap)：**
    *   全局禁用浏览器默认下拉刷新：`overscroll-behavior-y: none;`。
    *   Bottom Sheet 支持向下 Swipe 关闭（监听 `touchstart`, `touchmove`, `touchend` 计算 Y 轴位移）。
    *   浮层打开时，给 `<body>` 添加 `overflow: hidden` 防止底层 Stage 滚动。

---

## 3. 动效与状态驱动

坚持“克制、呼吸感、自然物理”的动效原则，全部由 Vanilla CSS/JS 实现。

*   **状态驱动映射 (Presence/State)：**
    *   `state: idle` -> `PresenceHalo` 缓慢呼吸（`transform: scale(1) to scale(1.05)`，时长 6s，`ease-in-out`，无限循环）。
    *   `state: thinking` -> `CompanionFigure` 增加轻微焦外虚化（`filter: blur(2px)`），`OutboxGlint` 产生流光效果（CSS `linear-gradient` background-position 动画）。
    *   `state: speaking` -> `SubtitleDialogue` 逐字浮现（通过 JS 拆分文本包裹 `<span>`，依次添加带有 `opacity: 1; transform: translateY(0)` 的 class，间隔 30ms）。
*   **动效节奏 (Timing & Easing)：**
    *   入场 (Enter)：`0.4s cubic-bezier(0.2, 0.8, 0.2, 1)`（减速进入，轻盈）。
    *   退场 (Exit)：`0.25s cubic-bezier(0.8, 0, 1, 1)`（加速离开，干脆）。
*   **性能限制：** 只对 `transform` 和 `opacity` 进行动画处理。避免对 `width/height/top/left` 做过渡。

---

## 4. prefers-reduced-motion 与低性能降级

尊重用户的生理需求，防止晕动症。

*   **CSS 媒体查询拦截：**
    ```css
    @media (prefers-reduced-motion: reduce) {
      *, *::before, *::after {
        animation-duration: 0.01ms !important;
        animation-iteration-count: 1 !important;
        transition-duration: 0.01ms !important;
        scroll-behavior: auto !important;
      }
      /* 针对特定状态的替代反馈 */
      .presence-halo { transform: none !important; opacity: 0.8; }
    }
    ```
*   **降级策略：**
    *   禁用 `PresenceHalo` 的呼吸缩放，改为静态发光。
    *   禁用 `MemoryConstellation` 的星空漂浮动画。
    *   Bottom Sheet 的滑出改为瞬间的 `display: block` 与简单的透明度渐变 (Crossfade)。

---

## 5. 声音与触觉建议

*   **Web Audio 规范：**
    *   **严格禁止自动播放 (No Autoplay)：** 必须由用户首次交互（如点击“进入温室”）解锁 AudioContext。
    *   **闪避机制 (Ducking)：** 当 `reply` 触发 TTS 语音时，JS 需控制背景环境音（如温室白噪音）的 GainNode 缓慢降至 20%，语音结束后恢复至 100%（Side-chain 模拟）。
*   **触觉反馈 (Haptics)：**
    *   仅在支持 `navigator.vibrate` 的移动端启用。
    *   微小交互（点击 `AirInput` 发送）：`navigator.vibrate(10)`（极其轻微的震动）。
    *   状态变更（`Task` 完成）：`navigator.vibrate([20, 50, 20])`（双重轻震，模拟心跳）。

---

## 6. 可访问性规范 (A11y)

*   **环境化 UI (Diegetic UI) 的语义化：**
    *   像 `MemoryConstellation`（记忆星图）这样的视觉化组件，必须包含 `.sr-only`（屏幕阅读器专用）的文本描述。
    *   例如：`<button class="star-node" aria-label="查看 10 月 12 日的记忆：第一次谈论电影"></button>`。
*   **焦点管理 (Focus Management)：**
    *   使用自定义的 `:focus-visible` 样式（如柔和的白色外发光 `box-shadow: 0 0 0 2px rgba(255,255,255,0.6)`），不破坏晶格温室的视觉一致性。
    *   打开 `TodaySheet` 抽屉时，JS 需将焦点 Trap（锁定）在抽屉内部，关闭时将焦点交还给触发按钮。
*   **字幕可读性：** `SubtitleDialogue` 必须满足 WCAG AA 级对比度。在复杂的背景下，字幕容器需加上底部的文字阴影或极度柔和的暗色渐变遮罩。
*   **ARIA 实时播报：** 
    *   字幕区域需设置 `aria-live="polite" aria-atomic="true"`，确保屏幕阅读器能读出 AI 的新回复。

---

## 7. 弱网、慢模型与服务端错误体验

保持陪伴感，不制造系统崩溃的恐慌。

*   **慢模型/长思考：** 超过 3 秒未返回 `reply` 时，不使用传统的 Loading 菊花图。`PresenceHalo` 转为缓慢的脉冲闪烁，并随机显示安抚性提示（如：“正在整理思绪...”），保持环境的宁静感。
*   **弱网/断网 (Offline)：** 监听 `window.addEventListener('offline', ...)`。界面不报错，而是让环境光线微微变暗，`SubtitleDialogue` 显示：“温室的信号似乎被云层遮挡了，我在这里陪你等风停。”
*   **局部数据失败：** 如果 `memory` 节点获取失败，不弹窗报错，仅隐藏 `MemoryConstellation` 入口，保证主聊天流正常运转。

---

## 8. 安全与隐私边界

这是最严厉的防线，确保底层逻辑与高风险内容不侵蚀用户的信任。

*   **`system_thinking` 前端绝对隔离：**
    *   在 `fetch` 响应的 JSON 解析阶段，立即执行清洗：
        `if ('system_thinking' in payload) { delete payload.system_thinking; }`
    *   **严禁**任何代码路径将该字段拼接到 DOM 或 `console.log` 中。
*   **`role_thinking` 的折叠呈现：**
    *   作为角色的“内心戏”，默认折叠，显示为“...”或“（思考中）”。
    *   点击展开后，样式必须与主 `reply` 明显区分：使用更小的字号、斜体、降低透明度（如 60%），传达“这是过程，不是最终对话”。
*   **高风险状态 (Safety Flags) 降噪：**
    *   当 API 返回高风险标记时，**不要**显示红色的警告框（避免刺激用户）。
    *   界面色调自动过渡为冷静的冷白光（Cool White）。
    *   暂停一切主动搭话 (`proactive`)。
    *   在输入框侧边提供一个低调的盾牌 Icon（`NotificationBoundary`），点击展开温和的边界提示与心理干预/审计链接。
*   **隐私模式 (Privacy Screen)：** 
    *   当页面通过 Page Visibility API 侦测到 `document.hidden` 或用户长时间无操作（10分钟）时，整个 Stage 加上 `backdrop-filter: blur(10px)`，保护屏幕内容不被旁人窥视。

## 1. 390x844 移动端验收规格

基于基准设备（如 iPhone 12/13/14 等 390x844 逻辑像素机型），确保沉浸感与交互可用性。

*   **Safe-area (安全区)**：
    *   顶部需预留 `47px`（刘海/灵动岛避让），底部预留 `34px`（Home Indicator 避让）。
    *   **不可接受**：任何可交互元素（按钮、输入框）侵入安全区。
*   **首屏人物 (Avatar/Character)**：
    *   **尺寸/比例**：占据屏幕中上部，高度占比保持在 `45% - 55%`（约 380px - 460px）。

    *   **布局**：固定于 AirInput 上方 `16px` 处。最大显示 2 行，超出则尾部省略（`...`）或平滑向上滚动。
    *   **不可接受**：单行字数过少导致频繁换行；文字与背景对比度低于 4.5:1。
*   **AirInput (输入区)**：
    *   **尺寸**：默认高度 `48px`，圆角 `24px`，悬浮于底部安全区上方 `16px`。
    *   **键盘打开状态**：键盘弹起时，AirInput 必须**无延迟贴合**键盘顶部推起。此时首屏人物需触发 `scale(0.85)` 的缩小或上移缓动，腾出空间。
    *   **不可接受**：键盘遮挡输入框；推起动画卡顿或出现白色闪烁底图。
*   **入口物件 (Entry Objects)**：
    *   **布局**：统一收纳于屏幕右上角（安全区下 `12px`，右侧 `16px`），图标尺寸 `32x32px`。
*   **Bottom Sheet (底部面板)**：
    *   **尺寸**：展开高度最高不超过视口的 `85%`（约 717px）。必须包含 `4x36px` 的顶部拖拽指示条（Drag Handle）。
    *   **不可接受**：展开时没有半透明黑色遮罩（Scrim，透明度 40%）；无法通过向下轻扫（Swipe down）关闭。

    *   **不可接受**：在 DND 期间仍有高频闪烁或高饱和度色彩。

*   **TodaySheet (今日面板)**：
    *   **文案与视觉**：顶部需明确展示状态标签（如 🌙 *“栖光已进入静默时段”* 或 🛑 *“今日交互已达上限”*）。
    *   **可操作项**：允许用户查看历史记录、修改设置。
    *   **不能做什么**：禁用（Disable）或隐藏发起新对话的主 CTA 按钮；禁止在面板内自动播放任何音视频。

# Batch 3B：审计调试、渐进式重构路线与验收清单

本规范定义了「栖光 luminous」从“工具化界面”向“晶格温室”演进的最后一块拼图：如何优雅地处理复杂的技术审计需求，同时不破坏沉浸式的陪伴体验。

---

## 1. 审计与深层调试体验原则

### 1.1 为什么 Trace/Ledger/Jobs 不进入主体验
*   **认知负荷隔离：** 陪伴空间的核心是“当下”与“情感”，而 Trace（追踪）和 Ledger（账本/逻辑链）代表了“过去”与“计算”。将两者混淆会导致用户产生被监视感或系统工具感。
*   **视觉纯净度：** 晶格温室需要大量的负空间（Negative Space）来营造呼吸感，高密度的调试日志会破坏这种美学。

### 1.2 三种视角的区分
*   **普通用户 (User)：** 仅感知“隐私抽屉”。关注点：我的数据在哪？我能删掉它吗？
*   **隐私审计 (Auditor)：** 关注“数据流向”。通过导出功能和简化的审计事件摘要，确认系统没有违规操作。
*   **开发者 (Dev)：** 关注“逻辑链路”。通过 Debug 面板查看 `/api/trace` 的原始时序和 `/api/ledger` 的推理成本。

---

## 2. 组件规格：PrivacyAuditDrawer (隐私审计抽屉)

该组件是用户与系统透明度之间的桥梁，采用“柔和透明”的视觉语言。

*   **职责：** 提供数据导出、记忆清除、隐私政策说明及关键事件摘要。
*   **DOM 建议：** `<aside id="privacy-drawer" class="drawer-hidden">`，内置于 `body` 直接子级，使用 `fixed` 定位。
*   **API 映射：**
    *   `GET /api/export`: 触发数据下载。
    *   `POST /api/memory/forget`: 针对特定记忆条目的删除操作。
    *   `GET /api/trace`: 提取最近 5 条关键行为摘要（如：同步了日历、更新了心情）。
*   **状态管理：** `isOpen`, `isExporting`, `lastAuditTimestamp`。
*   **视觉细节：**
    *   背景：`backdrop-filter: blur(20px) saturate(180%);`
    *   文案：使用“去技术化”语言。例如，不显示“DELETE_RECORD”，显示“抹除这段记忆”。
*   **验收标准：**
    *   从主界面边缘滑动或点击底部微小图标唤起。
    *   导出操作需有明确的进度反馈（Loading 状态）。
    *   手机端占据 90% 宽度，PC 端占据右侧 400px。

---

## 3. 组件规格：DebugTracePanel (深层调试面板)

这是系统的“机房入口”，仅在特定条件下开启。

*   **功能覆盖：**
    *   **Trace 流：** 实时滚动显示 `/api/trace`。
    *   **Ledger 视图：** 展示 `/api/ledger` 中的推理步长、Token 消耗、决策权重。
    *   **Jobs 状态：** 监控后台异步任务（如：向量数据库索引更新）。
*   **权限/显隐策略：** 
    *   默认隐藏。
    *   激活方式：快速点击 Logo 5 次，或 `Ctrl + Shift + D`。
*   **视觉规范：** 
    *   采用“暗色矩阵”风格（与主色调形成对比）。
    *   等宽字体 (JetBrains Mono / Cascadia Code)。
    *   高密度布局，支持折叠 JSON 树。
*   **性能影响：** 
    *   开启时才建立轮询或监听。
    *   限制 DOM 节点最大数量（如仅保留最近 200 条记录），防止长时间挂载导致页面卡死。
*   **错误状态：** 红色高亮显示 5xx 错误，并提供一键复制错误堆栈的功能。

---

## 4. 从当前 index.html 到晶格温室的三阶段重构路线

### 阶段 1：视觉骨架 (Visual Skeleton)
*   **目标：** 建立晶格布局，实现背景呼吸效果。
*   **保留 API 逻辑：** 维持现有 `fetch` 逻辑，仅更改数据渲染的目标容器。

# Batch 3B Supplement：`/api/jobs` 后台任务审计映射

## 1. 挂载位置与默认隐藏策略
*   **挂载位置**：无缝集成于 `DebugTracePanel`（调试追踪面板）的底部抽屉或右侧边栏中，作为独立的 “Jobs Audit” Tab 存在。
*   **隐藏策略**：默认处于 **DOM 级销毁状态**。仅当满足开发者唤醒条件（如 URL 携带 `?sys_debug=true` 或在设置页连续点击版本号 7 次）时，才动态加载并渲染该模块，避免污染正常用户的 DOM 树。

## 2. 任务状态视觉与交互映射
针对 `/api/jobs` 返回的 `status` 字段，执行以下精确的视觉映射：
*   **Running (执行中)**：`#1890FF`（栖光蓝）。左侧 icon 使用匀速旋转的 Spinner，背景辅以极弱的呼吸高光。
*   **Success (已成功)**：`#52C41A`（成功绿）。显示实心 Check icon，并附加淡入的完成时间戳（如 `in 2.3s`）。
*   **Failed (已失败)**：`#FF4D4F`（警示红）。状态栏高亮，**支持点击展开**，展示下发的 `error_message` 或 Stack Trace 缩略信息。
*   **Queued (排队中)**：`#FAAD14`（琥珀黄）或中性灰。使用虚线边框或沙漏 icon，表示任务已入队但未被 Worker 消费。
*   **Stale / Unknown (僵死/未知)**：`#722ED1`（暗紫）或带有 `?` 徽标的灰色。用于标识超时、失去心跳或 Worker 意外崩溃的孤儿任务。

## 3. 与 `/api/trace`、`/api/ledger` 的上下文联动
*   **Trace 联动 (链路追踪)**：在 Job 详情卡片中，若存在 `trace_id`，提供「查看执行链路」快捷按钮。点击后面板自动切换至 Trace Tab，并以该 `trace_id` 为过滤条件重新请求 `/api/trace`。
*   **Ledger 联动 (账本对账)**：若该后台任务涉及积分、权益或资产结算（如包含 `ledger_tx_id`），在卡片底部生成「审计账本」超链接，点击跳转至 Ledger 视图并高亮对应流水，实现“任务 -> 链路 -> 资金”的闭环审计。

## 4. 权限与入口规则
*   **普通用户隔离**：前端鉴权层强拦截。若当前用户 `role` 为普通用户，即使强行注入 debug 参数，前端请求拦截器也会直接 Block 对 `/api/jobs` 的请求，确保零数据泄露。
*   **开发/审计可见**：需满足 **双重校验**：当前用户 Token 解析包含 `admin`、`developer` 或 `auditor` 角色，**且**前端处于 Debug 模式，方可解锁入口并正常发起请求。

## 5. 错误与弱网状态处理
*   **弱网降级**：当 `/api/jobs` 请求延迟超过 2000ms 时，列表区平滑过渡为骨架屏（Skeleton），并显示「正在同步队列状态...」的微提示，避免用户误判为 UI 卡死。
*   **错误阻断**：若接口返回 403（权限失效）或 5xx（队列服务宕机），触发局部 Error Boundary。面板内显示轻量级断态组件（如“无法连接到任务调度中心”），并提供「手动重试」按钮，**绝不能**导致整个 `DebugTracePanel` 崩溃。

## 6. 体验与工程自检清单 (Checklist)
- [ ] **轮询销毁**：切换离开 Jobs Tab 或关闭 `DebugTracePanel` 时，必须清除 `/api/jobs` 的短轮询定时器（或中止 SSE 链接）。
- [ ] **视觉验收**：5 种 Job 状态的颜色、Icon 及动画严格遵循上述规范，暗黑模式下色彩对比度符合 WCAG AA 标准。
- [ ] **越权测试**：使用普通测试账号登录，强制开启 Debug 面板，验证 Network 中无 `/api/jobs` 请求发出。
- [ ] **联动传参**：验证从 Job 卡片跳转至 Trace / Ledger 时，上下文 ID 参数传递准确无误，无白屏现象。
- [ ] **容错测试**：通过 DevTools 模拟 Offline 或 Slow 3G，确认骨架屏及局部重试机制按预期工作。
