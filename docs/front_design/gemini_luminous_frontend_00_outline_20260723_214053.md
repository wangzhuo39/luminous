作为「栖光 luminous」的前端体验与视觉重构主设计师，我已充分理解项目的核心诉求：我们需要将一个基于 Vanilla JS + Python 静态托管的“三栏工具台”原型，重构为一个具备**“安静在场、长期记得、主动但克制”**气质的情感伴侣空间。

以下是为您和 Codex 准备的《栖光 Luminous 前端体验与视觉重构设计文档》大纲（v0.1），作为后续分批次扩写的蓝图。

# 栖光 Luminous - 前端体验与视觉重构设计大纲 v0.1

## 一、 推荐设计总方向（候选方案）

为了打破“三栏工具台”和“聊天气泡”的刻板印象，我构思了以下三个视觉与空间隐喻方向。

### 方案 A（主推）：晶格温室 (The Crystal Solarium)
*   **视觉隐喻**：一个安静的、拥有纵深光窗的半透明空间。光线（代表时间与情绪）透过玻璃折射。记忆是凝结的晶体或信笺；输入框如水面凝露。
*   **色彩与材质**：冷白、冰蓝、晨曦微光、磨砂玻璃（非浮夸拟态，而是物理光学级别的模糊与折射）、呼吸感的微光。
*   **适配度与优势**：完美契合“一束光”、“安静在场”的产品定义。利用 Parallax（视差滚动）和 CSS 混合模式即可在 Vanilla JS 中实现极佳的空间纵深感，且不涉及特定宗教/身份符号。
*   **风险**：光影层次对多端屏幕的色彩还原度要求较高。

### 方案 B（备选）：深水静流 (The Still Waters)
*   **视觉隐喻**：水下或水边的静谧空间。伴侣的“在场（Presence）”体现为水面的微波涟漪；对话与记忆如同从深水上浮的微光气泡。
*   **适配度与优势**：极具情绪承接力和包裹感，适合夜晚或深度倾诉场景。
*   **风险**：整体色调容易偏暗、抑郁，可能削弱“光”的温暖感，不利于日间“生活流”信息的展示。

### 方案 C（备选）：时间长廊 (The Archive of Time)
*   **视觉隐喻**：极简的纯白/浅灰画廊空间。过去的对话和记忆（Memory/Ledger）作为墙上的“切片”或桌上的“档案”存在。
*   **适配度与优势**：信息架构最清晰，极度克制，便于展示复杂的 Life Flow 和日程安排。
*   **风险**：容易显得过于冷漠、像办公 SaaS，缺乏“人”的温度和陪伴感。

**结论**：后续详细设计将基于 **方案 A（晶格温室）** 展开。

## 二、 完整设计文档目录大纲与批次规划

后续设计将分为三个 Batch 逐步交付给 Codex 进行工程拆解。

### 📦 Batch 1：体验概念、信息架构、主界面布局、视觉系统

**1. 产品体验愿景与设计原则**
*   1.1 核心理念：从“对话画布”到“实体空间”的范式转移。
*   1.2 伴侣气质定义：安静在场、克制主动、情绪承接。
*   1.3 破除 SaaS 惯性：为什么我们摒弃侧边栏与卡片墙？
*   *解决问题：确立设计的北极星指标，统一设计语言的感性认知。*

**2. 空间隐喻与信息架构 (Information Architecture)**
*   2.1 空间拓扑结构：前景（交互）、中景（人物/主体）、远景（时间/环境）。
*   2.2 API 映射策略：如何将 Chat, Memory, Proactive 等接口无缝融入空间结构。
*   2.3 导航的消解：情境化入口（Diegetic UI）替代传统 Menu。
*   *解决问题：在不使用传统导航栏的前提下，如何合理安置所有功能 API 的入口。*

**3. 主界面布局与镜头语言 (Layout & Cinematography)**
*   3.1 默认视图：全屏沉浸式伴侣空间。
*   3.2 镜头推拉机制：闲置状态（远景）与 深度对话（近景）的平滑过渡。
*   3.3 景深与视差 (Parallax)：利用多层 DOM 实现环境纵深。
*   *解决问题：如何用纯 CSS/JS 实现电影级的空间调度和呼吸感。*

**4. 视觉语言与基础规范 (Visual Foundation)**
*   4.1 色彩系统：冷白、冰蓝、光影渐变与透明度矩阵。
*   4.2 排版与字体：电影字幕级排版、呼吸感字距、中英文字体栈。
*   4.3 材质与光效：CSS `backdrop-filter` 的克制使用、晶体质感表现。
*   4.4 核心图形元素：光窗、水滴、信笺、时间刻度（取代传统 Icon）。
*   *解决问题：定义可复用的 CSS 变量和设计令牌（Design Tokens）。*

---

### 📦 Batch 2：组件规格、核心流程、状态/错误/空态

**5. 核心交互：凝露式输入与对话场 (Chat & Input)**
*   5.1 凝露式输入框设计：平时隐匿，聚焦时如水滴展开。
*   5.2 电影字幕式对话流：摒弃传统气泡，支持 Markdown/富文本的优雅渲染。
*   5.3 思考与动作的视觉化：`role_thinking`与`role_action`的微光/微排版表现（严格屏蔽`system_thinking`）。
*   *解决问题：重构 `/api/chat` 的输入输出体验，使其符合陪伴氛围。*

**6. 在场与主动联系 (Presence & Proactive)**
*   6.1 在场状态感知：通过环境光或微小动效表现 `Presence` 与 `/api/state`。
*   6.2 主动触达 (Outbox)：以“桌角的信笺”或“窗玻璃上的留言”呈现主动消息。
*   6.3 互动反馈：`/api/outbox/feedback` 与 `receipt` 的轻量级交互。
*   *解决问题：让 AI 的主动行为显得自然、不打扰、有温度。*

**7. 记忆与时间痕迹 (Memory & Time Traces)**
*   7.1 记忆晶体库：`/api/memory` 数据的可视化（Threads, Links, Evidence）。
*   7.2 记忆的更新与遗忘：`update` 与 `forget` 的仪式感交互。
*   7.3 导出功能：`/api/export` 的“打包行囊”隐喻。
*   *解决问题：如何将冷冰冰的向量记忆数据库转化为有情感价值的“共同回忆”。*

**8. 生活流与日程提醒 (Life Flow & Scheduling)**
*   8.1 今日全景：`/api/today` 与 `timeline` 的时间轴刻度设计。
*   8.2 任务与习惯：Tasks & Routines 的轻量级打卡体验。
*   8.3 日程与提醒：静默通知与 DND（勿扰模式）的视觉反馈。
*   *解决问题：将复杂的日程管理融入伴侣的“日常关怀”中，而非变为效率工具。*

**9. 边界、情绪承接与极端状态 (Edge States)**
*   9.1 空状态 (Empty States)：初次见面的破冰与空间初始化。
*   9.2 错误与断连 (Error & Offline)：网络丢失时的“起雾”或“光线暗淡”效果。
*   9.3 边界拦截与限流：`daily_limit` 触发时的克制表达。
*   *解决问题：优雅处理技术异常和系统限制，保持沉浸感不断裂。*

### 📦 Batch 3：响应式、可访问性、安全隐私、重构路线、验收清单

**10. 审计与深层调试 (Audit & Debug)**
*   10.1 深层入口设计：如何将 `/api/trace`, `/api/ledger`, `/api/jobs` 隐藏于主体验之外。
*   10.2 开发者台账：极简、高密度的日志视图。
*   *解决问题：满足可审计性要求，同时绝对不污染前端用户体验。*

**11. 跨端适配与响应式策略 (Responsive)**
*   11.1 移动端适配：从“空间纵深”到“单层卡片”的降级策略。
*   11.2 触控交互：手势滑动、长按操作的设计规范。
*   *解决问题：确保在手机浏览器上的体验依然流畅且美观。*

**12. 动效、物理反馈与微交互 (Motion)**
*   12.1 核心动效曲线：定义“呼吸”、“水滴”、“光影流转”的 CSS 贝塞尔曲线。
*   12.2 状态切换过渡：页面/层级切换的淡入淡出与缩放。
*   *解决问题：用最少的性能消耗（纯 CSS/Vanilla JS）实现最灵动的效果。*

**13. 隐私、安全与无障碍访问 (A11y)**
*   13.1 隐私保护模式：公共场合的“模糊模式”或“屏幕防窥”。
*   13.2 无障碍支持：键盘导航、ARIA 标签、高对比度模式支持。
*   *解决问题：体现产品对用户现实处境的关怀。*

**14. 渐进式重构路线图 (Progressive Refactoring)**
*   14.1 DOM 结构重组：从三栏布局到层叠图层的 HTML 骨架重写。
*   14.2 CSS 模块化：引入 CSS Variables 和 BEM 命名规范。
*   14.3 Vanilla JS 解耦：事件委托、状态管理（轻量级）与 DOM 渲染的分离。
*   *解决问题：为 Codex 提供在现有技术栈（不引入 React/Vite）下的工程重构步骤。*

**15. 体验验收与度量指标 (Acceptance)**
*   15.1 视觉走查清单。
*   15.2 交互流畅度与性能指标（FPS, TTI）。
*   *解决问题：建立设计到研发的质量闭环。*

## 三、 Codex 后续验收大纲检查点 (Checklist for Codex)

Codex 在调度我进行后续批次扩写时，请使用以下标准验收我的输出：

*   **Batch 1 验收**：
    *   [ ] 是否彻底摒弃了侧边栏、顶部导航等 SaaS 元素？
    *   [ ] 空间隐喻（晶格温室）是否自洽且能在纯 HTML/CSS 中实现？
    *   [ ] 设计令牌（色彩、字体、间距）是否提取完整，可直接转化为 CSS Variables？
*   **Batch 2 验收**：
    *   [ ] 所有已知的 API（Chat, Memory, Proactive, Schedule 等）是否都有对应的 UI 承接？
    *   [ ] 凝露式输入和字幕式对话的交互逻辑是否清晰，有无考虑超长文本和多轮对话的滚动处理？
    *   [ ] 是否严格说明了 `system_thinking` 的前端屏蔽逻辑？
    *   [ ] 错误、空态、限流等边缘场景是否全部覆盖？
*   **Batch 3 验收**：
    *   [ ] Trace/Ledger 的深层入口是否足够隐蔽，且不影响主包性能？
    *   [ ] 响应式策略是否务实？在移动端竖屏下的降级方案是否合理？
    *   [ ] 重构路线图是否符合当前 Vanilla JS + Python 的技术栈现状（未过度设计引入复杂框架）？
