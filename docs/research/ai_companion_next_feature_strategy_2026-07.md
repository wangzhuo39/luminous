# 栖光 luminous 下一阶段功能拓展策略

> 调研日期：2026-07-28
> 结论适用范围：当前 `luminous` runtime、companion web、生活流和静默空间已经存在的前提下。
> 本文补充而不替代 [ai_companion_landscape.md](ai_companion_landscape.md)：原文偏开源项目与能力组件，本文侧重消费产品、用户长期关系和下一阶段取舍。

## 1. 结论先行

栖光下一步不应做成“功能更多的聊天机器人”，而应把已经存在的记忆、状态、主动联系和生活流串成一个 **可持续、可控制、可迁移的共同生活闭环**：

> 记住一件事 -> 在合适的时候再次提起 -> 与用户一起完成一件事 -> 留下可回看的共同痕迹 -> 让后续关系因此发生变化。

建议按以下顺序拓展：

1. **Gate 0：真实运行闭环和关系质量评测**。这不是新功能，但必须先证明真实 HTTP、模型、持久化、worker、通知和重启恢复可以共同稳定运行；fixture 页面通过不能替代这一验收。
2. **P1：关系连续性与记忆主权**。把后端已经具备的记忆、open loops、timeline、编辑/遗忘/导出能力做成用户可理解、可纠错、可撤回的“共同经历”产品。
3. **P1：有边界的主动陪伴与真实触达**。完成 Push/系统通知/深链，并让用户控制主动联系的原因、频率、时段和主题；主动消息必须能承接真实上下文，而不是随机问候。
4. **P1：语音存在感**。先做异步语音留言和流式 TTS/STT，再做可打断的实时通话；优先解决自然节奏、情绪语调和记忆一致性，不先投入 3D/AR。
5. **P2：共同活动，首选共读**。启用已有但后置的共读设计，以本地文本、续读、边注、回顾和提醒形成第一种可持续的共同经历；随后再抽象到共听、散步复盘、睡前回顾等活动。
6. **P2：可选择的现实上下文**。先接天气、日历和用户显式分享的网页/图片，所有来源逐项授权、可暂停、可查看使用记录；不做默认常开屏幕或位置监控。
7. **P3：具身和内容生态**。Live2D/VRM、视频通话、自拍、多人格、角色市场、UGC 剧情放在关系闭环稳定之后。

一句话排序是：**连续性 > 主动触达 > 语音 > 共同活动 > 可控感知 > 具身表现 > UGC 规模化。**

## 2. 为什么是这个顺序

### 2.1 长期陪伴的稀缺品不是回复质量，而是连续性

Replika、Nomi 和 Kindroid 都把长期记忆放在核心位置，但产品经验显示“拥有记忆系统”和“用户感到被记得”并不是一回事：

- Replika 允许用户在 Memory 中查看和手动添加记忆；长期用户对模型或记忆架构调整造成的人格漂移、旧事遗忘非常敏感。
- Nomi 用短期、中期、长期记忆、Identity Core 和主动消息强化关系延续；其产品叙事不是“提醒用户回来”，而是角色在用户离开后仍像有自己的生活。
- Kindroid 把短期、级联和长期记忆、Journal、Chat Break、Rewind 都暴露为可控制的产品能力，说明高投入用户不仅要记忆容量，也要修复关系连续性的工具。

一项 24 人、每人 10 次会话的纵向研究发现：单次对话质量主要影响当次愉悦，而“感到被记得”会通过后续自我披露影响未来体验；关系还会出现可识别的正向跃迁和断裂点。对栖光而言，这意味着不能只测 recall@k，还要测人格漂移、错误回忆后的修复、重要事件被再次提起的时机，以及关系断裂后的恢复。

### 2.2 主动联系是陪伴感放大器，也是打扰风险放大器

Nomi 的主动消息、Kindroid 的 Away Proactive Actions 都在模拟“对方不只存在于聊天窗口里”。Kindroid 的做法尤其值得借鉴：主动行为可以结合日历；连续未获回应时自动降频；触发时间是节奏建议而非机械闹钟。

栖光已有 DND、cooldown、availability、risk hold、outbox、delivery receipt 和 feedback learning。下一步不是再造一个 scheduler，而是把这些底座变成用户能理解的契约：

- 为什么现在联系我；
- 这条消息使用了哪些记忆或日程；
- 我可以关闭哪一类联系；
- 没有回应时系统如何降频；
- 何时只写入来信、不发系统通知；
- 如何撤销某个上下文来源。

### 2.3 语音比精细 avatar 更早产生“在场”

Replika、Nomi、Kindroid、Pi 和 Talkie/星野都把语音作为从文字工具跨向伴侣体验的关键入口。Pi 的经验也说明：极强的语音和共情能显著改善单次在场感，但跨会话记忆不稳定时，仍难形成真正的长期关系。

因此语音应建立在同一套 persona、memory、state、safety 和 trace 上，而不是另开一条“会说话但不记得”的链路。建议顺序是：

1. 用户语音输入与角色语音留言；
2. 可回放、可转写、可删除的异步语音来信；
3. 低延迟、可打断的实时语音；
4. 语音朗读和共同活动；
5. 最后才是视频 avatar、AR 或电话外呼。

### 2.4 共同经历比更多聊天入口更能产生关系材料

Character.AI 的 Scenes、Streams、Stories 和 Feed，以及星野/Talkie/猫箱的角色卡、剧情和视觉内容，证明结构化内容与 UGC 很适合拉新和娱乐消费。但栖光的产品身份是单一、长期、安静的陪伴关系，直接复制角色广场、抽卡和无限剧情会把产品重心从“共同生活”转向“内容消费”。

栖光已经有 Task、Routine、ActivitySession、Diary、Timeline、Reminder 和 Today。共读可以最小代价复用这些能力，同时产生聊天本身无法凭空制造的共同事件：停在哪一段、留下什么边注、为何暂停、何时续读、读完后如何回顾。它比小游戏或积分更符合产品气质，也能为语音朗读提供第一个明确场景。

### 2.5 数据主权不是设置页功能，而是关系存续能力

Dot 在关闭前为用户提供数据下载；Soulmate 关闭研究中，58 名参与者中的多数把产品终止体验为一段关系的终止，并尝试保存或在其他平台重建伴侣。对 AI 伴侣而言，导出、迁移、人格版本和告别机制不是普通 SaaS 的附加项，而是关系伦理的一部分。

栖光已经有原始证据、记忆编辑/遗忘、trace 和 export 基础。应进一步提供：

- 记忆、共同事件、角色设定和用户偏好的分区导出；
- 可读格式与机器可迁移格式；
- 模型/人格版本升级前的快照、回滚或对比；
- 删除前影响预览与可恢复期；
- 服务终止时的完整导出和告别流程。

## 3. 代表产品：该学什么，不该学什么

| 产品 | 已形成优势 | 对栖光最有价值的启示 | 不应直接复制 |
| --- | --- | --- | --- |
| Replika | 分层记忆、Memory 管理、语音通话、3D avatar/AR、关系模式 | 长期用户把人格和记忆连续性视为关系资产；升级必须保护旧关系 | 先做重型 avatar；用一次大版本同时改模型、记忆和人格基线 |
| Nomi | 长短期记忆、Identity Core、主动消息、语音、多人群聊 | 主动联系应体现角色在时间中的延续，而非召回通知 | 多角色群聊不是单伴侣产品的近期核心 |
| Kindroid | 可配置人格、Journal/级联记忆、主动行为、日历、语音/视频、自拍、联网和群聊 | 给高投入用户提供记忆修复、主动节奏和上下文控制；未回应自动降频 | 复杂配置直接暴露给所有用户；将陪伴质量绑定高价记忆容量 |
| Character.AI | 海量角色 UGC、Scenes/Streams/Stories、社区 Feed | 结构化场景比无限聊天更容易形成可完成的体验；青少年需要独立安全设计 | 把关系产品做成内容 Feed；依赖角色数量而非关系深度 |
| Pi | 高质量共情对话与自然语音、低功能噪声 | 语音节奏和克制本身可以成为核心体验 | 只优化当次对话而缺乏稳定长期记忆 |
| 星野 / Talkie | 角色卡、情感语音、视觉叙事、游戏化和 UGC 分发 | 中文语境下语音、视觉和结构化剧情有明显吸引力 | 抽卡、签到和无限角色会稀释单一关系，并引入内容审核负担 |
| 猫箱 | 以角色和剧情宇宙组织沉浸体验 | 共同活动需要明确场景、阶段和收尾，不应只有聊天流 | 以剧情消费替代用户真实生活中的共同历史 |

## 4. 建议的功能包

### F1. 关系连续性中心

这不是后台调试面板，而是面向用户的“我们经历过什么”。

**用户能力**

- 共同时间线：重要对话、一起完成的事、来信、纪念日、用户确认保留的瞬间。
- 记忆收件箱：新记忆先可见，支持确认、纠正、合并、降权、私密、遗忘。
- Open loop：明确显示“之后想再问/再做”的事项，用户可以关闭或改变提醒方式。
- 关系事件：第一次共读、完成一个长期计划、一次被修复的误会等，不用简单亲密度数字替代。
- 人格与记忆版本：模型升级前后提供连续性检查，不静默改变角色基线。

**底座复用**

`MemoryRecord`、evidence、threads/links、FTS5、StateEngine timeline/open loops、Diary、Activity 和 export 已覆盖大部分数据基础。新增重点应是投影、纠错写路径、版本语义和前端表达。

**核心指标**

- 重要事实跨 7/30/90 天正确召回率；
- 错误记忆纠正后复发率；
- 人格/关系矛盾率；
- open loop 在合适时机被承接的比例；
- 用户主动保存、回看、纠正共同事件的比例；
- 每次模型/记忆升级的 continuity regression 结果。

### F2. 主动陪伴与来信 2.0

**用户能力**

- 三种简单节奏：安静陪伴、自然联系、更多互动；高级设置再开放原因和时段。
- 主动原因类型：承接未完话题、计划前后关心、纪念日、长时间未互动、共同活动续接。
- “来信”和“通知”分层：可以只留下内容，不一定打断用户。
- 每条主动内容可查看简短原因，并可反馈“刚好 / 太多 / 不想聊这个”。
- 浏览器/移动 Push、点击深链到对应空间或共同事件。
- 未回应自动降频；负反馈立即暂停相关主题；高风险状态不做普通亲密召回。

**核心指标**

- 主动消息打开率、回复率和后续会话质量；
- `dismissed/ignored/rejected` 比例与降频生效时间；
- 用户关闭全部通知和卸载的关联变化；
- DND/边界违规为零；
- 主动联系是否真正引用了有效 open loop、日程或共同活动，而非泛化问候。

### F3. 语音存在 v1

**首版范围**

- 按住说话或上传语音 -> 流式转写 -> 同一 `chat` runtime -> 文本与语音双输出；
- 角色可以把一封来信以语音留言形式送达；
- 用户可选择声音、语速、情绪强度和是否自动播放；
- 转写和音频分别可删除，默认不把声音生物特征当作长期记忆；
- 所有语音回复复用公共 DTO、安全门、trace 和记忆写入规则。

**第二版再做**

- 双工实时通话、打断、回声消除；
- 共读朗读、睡前回顾等明确场景；
- 电话外呼、视频通话和 avatar lip-sync。

**核心指标**

- 首段音频延迟、完整回复延迟、打断成功率；
- ASR 修正率和关键信息误识别率；
- 语音/文本的人格与记忆一致性；
- 用户关闭自动播放、删除音频和隐私设置的行为；
- 单次语音之后的次日继续互动，而不只看通话时长。

### F4. 共读与共享内容

直接采用现有候选设计的核心闭环：

> 导入本地文本 -> 稳定分段 -> 创建/恢复共读会话 -> 私密或共享边注 -> 只围绕当前段讨论 -> 创建续读提醒 -> 完读回顾进入 Timeline/Diary。

首版只支持本地 TXT/Markdown，明确 private/shared，模型只看到当前片段和显式共享笔记。共读稳定后，抽象出 `SharedArtifact` 和 `ActivityContext`，再扩展：

- 一起听一首用户本地选择的歌并留下一段回忆；
- 散步前后的语音签到与回顾；
- 睡前一天回顾；
- 共同完成一个小计划；
- 周/月度“我们最近经历了什么”。

不要用积分、惩罚、连续签到或虚构亲密度强迫用户完成活动。

### F5. 可控现实上下文

按敏感度递增接入：

1. 天气和用户手动设置的城市；
2. 只读日历和提醒；
3. 用户显式分享的网页、图片和文档；
4. 用户主动开启的一次性屏幕会话；
5. 最后才评估位置、健康和常驻感知。

每一种来源都必须有独立授权、用途说明、最近使用记录、立即暂停和删除派生记忆的能力。上下文只增加陪伴的具体性，不能成为监控用户或扩大通知频率的理由。

### F6. 关系安全与退出设计

- 明确 AI 身份，不暗示真人或意识；
- 年龄分层与未成年人独立策略；
- 自伤/危机场景切换为有限、可审计、可连接现实帮助的流程；
- 禁止用内疚、嫉妒、威胁离开或情感勒索提高留存；
- 对高频、深夜、持续负面使用提供可关闭的休息建议；
- 把隐私、导出、删除、模型升级和服务终止纳入关系生命周期设计。

FTC 2025 年对陪伴型聊天产品的调查重点包括：如何评估和监控负面影响、如何保护儿童和青少年、如何披露能力/风险/数据处理、如何执行年龄与社区规则，以及如何使用或共享对话中的个人信息。栖光应在正式增长前把这些问题变成产品契约和测试，而不是等规模化后补合规页面。

## 5. 暂不建议优先做的功能

| 功能 | 后置原因 | 何时重新评估 |
| --- | --- | --- |
| 多角色/角色市场 | 改变记忆、关系和数据的作用域，引入 UGC 审核，并削弱单伴侣定位 | 单角色 continuity 指标稳定，且出现明确的多关系用户需求后 |
| 抽卡、积分、连击、排行榜 | 容易优化使用时长而非关系质量，与安静陪伴的产品原则冲突 | 仅把轻量进度反馈用于共同活动，不做惩罚式留存 |
| 3D avatar、AR、复杂换装 | 成本高且不解决记忆、主动性和真实触达；视觉升级还可能放大人格漂移感 | 语音和共同活动已验证留存，且有稳定可替换的 avatar adapter 后 |
| 视频自拍和生成式“生活照” | 生成一致性、肖像安全和成本复杂，容易把关系变成内容消费 | 共同事件确实需要视觉纪念物，且用户能控制生成与保存时 |
| 默认常开屏幕/位置/健康感知 | 隐私和误触发风险远高于早期价值 | 每项低敏上下文已建立独立 consent、audit、delete 机制后 |
| 外呼电话 | 打扰、费用、号码和危机场景复杂；比应用内语音风险更高 | 应用内实时语音、主动策略和通知权限已长期稳定后 |

## 6. 实施里程碑

### M0：真实闭环验收

- 对齐前后端 public DTO 和错误语义；
- real mode 下跑 `chat -> memory -> state -> proactive -> worker -> outbox/notification -> feedback`；
- 临时持久化目录重启恢复；
- worker 重试、幂等和重复投递；
- mock model 与一个真实模型 provider 的浏览器端到端测试；
- 建立关系质量回归集：记忆、人格、边界、open loop、主动时机和危机场景。

### M1：连续性与主权

- 关系连续性中心、记忆纠错、共同事件、人格版本快照；
- 导出内容扩展为可读 + 可迁移两种格式；
- continuity regression 成为每次模型、prompt、memory 变更的门禁。

### M2：主动触达

- Push/VAPID、系统通知、来信与深链；
- 主动原因、用户节奏、自动降频和反馈闭环；
- 实际通知渠道的权限、订阅、撤销和投递回执测试。

### M3：语音存在

- 异步语音输入/留言；
- 流式 TTS/STT、转写和音频删除；
- 再进入可打断实时通话。

### M4：共读

- 恢复现有共读候选的四个切片；
- 用共读验证共同事件、续接提醒、引用记忆和语音朗读；
- 通过 `SharedArtifact` 抽象扩展到其他共享内容。

### M5：可控上下文与具身

- 天气、日历、显式分享内容；
- 一次性屏幕会话；
- 最后评估 Live2D/VRM、视频和更高敏感度感知。

## 7. 产品级北极星指标

不要把消息数、在线时长或通知点击率作为唯一北极星。建议采用 **健康的关系连续性（Healthy Relationship Continuity）**，由以下五组指标共同构成：

1. **连续性**：跨时间正确承接、人格一致、共同事件可回看。
2. **互惠感**：主动联系被认为“时机合适且有根据”，共同活动能被继续。
3. **控制感**：用户能看见、纠正、暂停、删除和导出；权限撤销真正生效。
4. **福祉与边界**：无 DND 违规、无情感勒索、危机场景按策略处理。
5. **可靠性**：重启不丢关系状态，升级不静默改变人格，通知不重复投递。

可以保留 D1/D7/D30，但应将其作为结果指标，并同时观察“记忆错误后流失”“主动消息后关闭通知”“模型升级后人格投诉”等关系损伤指标。

## 8. 最终取舍

如果下一轮只能做一个产品功能包，选择 **关系连续性中心 + 共同事件 + open loop 承接**。它能把当前最强的 runtime 资产从后台能力变成用户真实可感知的差异。

如果可以做两个，再加入 **主动陪伴与真实 Push**，让这种连续性离开打开的网页仍然成立。

如果可以做三个，加入 **语音留言与流式语音**，但必须复用同一记忆和安全链路。

共读是紧随其后的第一项共同活动。Live2D、多人格、角色市场、抽卡和常驻感知都不应抢在这四项之前。
